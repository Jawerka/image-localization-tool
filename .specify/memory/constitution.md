# Image Localization Tool Constitution

## Core Principles

### I. Пайплайн v2

Обработка страницы обязана идти через пайплайн v2. Новый путь распознавания, перевода или очистки не подменяет этот вход.

### II. Минимальный diff

Изменение обязано оставаться настолько малым, насколько хватает для задачи. Новый движок — новый файл в `src/components/`. Новая настройка — поле в `Config` со значением по умолчанию.

### III. Русский язык

Комментарии и docstring пишутся на русском.

### IV. Локальные данные

Пользовательские данные лежат только в папке программы: `data/`. Кэш загрузок — `.downloads/`, компоненты — `models/`, `.resources/` и `runtime/`. `%APPDATA%` и `%LOCALAPPDATA%` не используются.

В репозиторий не попадают `models/`, `config.json`, `test-img/`, `data/`, `output/`, `.vendor/`, `legacy/`, `.downloads/`, `runtime/`, `.resources/`, `dist/`, логи и секреты. Ключ API не записывается в JSON.

### V. Заявленное качество

Число ink recall с локальных эталонов относится только к этим страницам. Его нельзя называть качеством на произвольной странице. Источник цифры — `docs/BENCHMARK_RESULTS.md`.

## Границы совместимости

CLI (`src/main.py`), Flutter-хост с сайдкаром `--api`, окно из исходников (`python -m src.app`), браузерный редактор (`--server` и Docker), Linux-служба, расширение браузера и LAN-слушатель остаются на месте. Новая фича не убирает существующий вход и не меняет контракт соседней поверхности без отдельного требования.

Базовое состояние продукта зафиксировано в `specs/001-current-state/spec.md`. Новая спецификация описывает изменение относительно неё.

## Известные ловушки

- RT-DETR `orig_target_sizes` — `[ширина, высота]`.
- LLM обрабатывает запросы по одному. Пустой `llm_model` резолвится через `/v1/models`.
- LaMa дорисовывает буквы, если кольцо однородности захватывает соседний текст.

План, который нарушает одну из этих границ, обязан явно назвать причину.

## Завершение фичи и ветки

Фича разрабатывается в отдельной ветке. После реализации, необходимых проверок и фиксации результатов изменения обязаны проходить через Pull Request (PR) в `main`. В PR указываются итоговое поведение, выполненные проверки и оставшиеся ограничения. Невыполненные требования не объявляются выполненными: они явно отмечаются как отсроченные либо остаются открытыми.

Слияние выполняется после успешных обязательных проверок и устранения блокирующих замечаний. PR не означает отдельного релиза или деплоя. Агент создаёт PR и сливает его только при наличии соответствующего разрешения пользователя; завершение реализации само по себе не разрешает публикацию или слияние.

После успешного слияния локальная `main` обновляется, а завершённая рабочая ветка удаляется локально и на сервере. Перед удалением проверяется, что её изменения включены в `main`; ветки с невключённой работой сохраняются. Между фичами единственная постоянная ветка проекта — `main`.

## Governance

Поправка конституции требует записанной причины, оценки совместимости с уже принятыми принципами и новой версии по semver. MAJOR — принцип удалён или переопределён. MINOR — принцип или раздел добавлен. PATCH — уточнение формулировки без смены правила.

Проверка соответствия этой конституции входит в ревью плана и реализации фичи. Исключение из принципа записывается в плане, а не подразумевается.
