# Implementation Plan: Цвет ручных правок маски

**Branch**: `codex/050-mask-delta-overlay` | **Date**: 2026-10-20
**Spec**: [spec.md](spec.md)
**Статус**: Реализовано; автоматические проверки пройдены, ручная приёмка — по quickstart.

## Summary

Строить один визуальный слой: чёрный негатив существующей маски, затем непрозрачные зелёные/красные следы из `document.strokes` в порядке записи, затем активный мазок. Наложить полученный слой на страницу один раз с opacity 0.5 и обычным смешиванием.

Цвет — только представление редактора. Не нужны серверная цветная маска, новый endpoint, миграция документа или копия автоматической маски.

## Что найдено в текущем коде

### Desktop

- `apps/desktop/lib/src/ui/viewer/canvas_painter.dart`, `ScenePainter._paintScene`: серверная картинка `mask` рисуется через `BlendMode.multiply` с альфой `0x80`. Белое не меняет страницу, чёрное затемняет.
- `_paintPreviews`: только активный мазок зелёный/синий (`0x8C16A34A` / `0x8C2563EB`); законченные `document.strokes` отдельно не рисуются.
- `canvas_view.dart`, `_commitStroke`: добавляет Stroke через `editDocument(..., deferApply: true)`, затем очищает `session.strokePoints`.
- `state/viewer_state.dart`: документ, история, изображения; `imageFor` может возвращать прошлую версию картинки той же страницы до декода новой.
- `model/page_document.dart`: Stroke уже содержит mode/radius/points, режимы paint/erase/fill/erase_fill.

### Web

- `web/js/viewer.js`, `paintLocalMask`: серверная маска + мазки белым/чёрным.
- `syncMaskDraft` держит локальную маску только при черновике/ожидании сервера, затем очищает.
- `drawStroke` / `drawPolylineDraft`: отдельный SVG-предпросмотр зелёного/синего цвета.
- `web/js/mask_draft.js`: нормализация, геометрия мазков, решение paint/wait/clear.
- `web/css/editor.css`: `.frame__mask` использует multiply и opacity 0.5.

### Сервер — опорная семантика, без изменений

- `src/components/text_segmenter.py`, `apply_strokes`: 255 добавляет, 0 вычитает; операции по порядку. Геометрия OpenCV: круги, линии толщиной 2r, fillPoly, LINE_8.
- `src/page_pipeline.py`, `clean`, и `src/app/worker.py`, `_save_mask`: сохранённый PNG уже включает ручные мазки.
- Эти мазки используются как цветовые метки назначения, а не как новая разница относительно PNG.

## Логика отображения

### 1. Значение цвета

| Последнее действие в пикселе | Отображение |
|---|---|
| Нет действий, значение маски 0 | Чёрный 50% |
| Нет действий, значение маски 255 | Прозрачно |
| paint / fill | Светло-зелёный #90EE90, 50% |
| erase / erase_fill | Светло-красный #FF9999, 50% |

Промежуточный серый сохраняет плавность: alpha чёрного = `0.5 × (1 − M/255)`.

«Кисть → ластик» даёт красный, даже если значение вернулось к исходному. Undo ластика возвращает зелёный. Undo всех ручных назначений возвращает базовый вид (для применённых правок — после актуализации серверного PNG).

Цвет остаётся после «Готово», смены страницы и открытия проекта. Если операция приложения удалит strokes, исчезают соответствующие цветные метки.

### 2. Единый слой

```text
overlay = transparent
если доступна подходящая mask:
    overlay.rgb = black
    overlay.alpha = 1 - mask.gray / 255
для stroke в document.strokes по порядку:
    нарисовать геометрию непрозрачным green или red поверх overlay
если есть активный stroke:
    нарисовать его тем же способом
отрисовать overlay на странице с общей alpha=0.5, srcOver
```

Не оставлять чёрное затемнение под цветом. Не задавать 0.5 каждому мазку отдельно: пересечения начнут темнеть. Не применять multiply к цветам: они теряются на тёмном фоне.

На сглаженной границе допустимо смешение покрытия; внутри мазка последнее действие полностью заменяет предыдущее. Геометрия временного и законченного мазка должна совпадать.

### 3. Жизненный цикл

- Pointer down/move: активный мазок рисуется последним в том же слое.
- Pointer up: мазок переносится в документ, временное состояние очищается без кадра с двойной заливкой.
- Отмена жеста: исчезает только временный след.
- Undo/redo: цвета перестраиваются из текущего списка. Отдельная история цветов не нужна.
- Сброс черновика: цвета следуют документу, перечитанному с сервера.
- «Готово»: цвета остаются. Новый PNG обновляет базовую часть, не обнуляя метки.
- showMask=false: скрыть весь композит, включая заливку активного мазка; оставить курсор/контур инструмента.
- Смена страницы/проекта: очистить временные ресурсы и жест; запретить чужие изображения.
- Маска отсутствует/не готова: прозрачная база + ручные следы, без сплошного чёрного фона.
- Поздние ответы: проверять page/project/generation. Версия в URL сама по себе не доказывает завершение пересчёта; учитывать существующий статус/событие обновления страницы.
- Undo применённого мазка: метки меняются сразу, база может обновиться позже. Сохранить существующее ожидание пересчёта; не обещать мгновенную новую бинарную маску.

## Изменения кода по файлам

### Шаг 1. Контракт и примеры

Зафиксировать палитру, порядок действий, маленькие синтетические маски. Одинаковые сценарии для Dart и JS: чёрная/белая половины, пересекающиеся мазки, точка, обе заливки.

### Шаг 2. Desktop-композитор

**Новый `apps/desktop/lib/src/ui/viewer/mask_overlay_painter.dart`**:

- Палитра и отрисовка геометрии Stroke.
- Входы: mask image, page bounds, список мазков, активный мазок.
- Ограничить рисование прямоугольником страницы; открыть saveLayer с общей альфой 0.5.
- Нарисовать mask как чёрный с обратной альфой. Кандидат: ColorFilter.matrix с RGB=0, alpha=255−R для непрозрачного grayscale PNG. Проверить растровым тестом, включая серые значения.
- Последовательно нанести непрозрачные цветные следы с srcOver; закрыть слой.
- Координаты/радиус согласовать с сохранением и сервером; точка — круг, заливка требует минимум три точки.
- Не выполнять toByteData() для маски внутри каждого paint.

**`canvas_painter.dart`**:

- В `_paintScene` заменить multiply-блок композитором под viewer.showMask.

- Удалить отдельную заливку кисти из `_paintPreviews` во избежание двойного смешивания.
- Для незаконченного лассо оставить только контур и маркеры, сменить синий на красный. Заливка появится при commit.
- Сохранить текущий порядок относительно текстового превью/рамок и отсутствие перехвата ввода.

**`canvas_view.dart`**:

- Проверить `_commitStroke` и отмену жеста: активный и сохранённый след не должны удваиваться на кадре.

**`viewer_state.dart`**:

Начать с прямой Canvas-композиции. Сложный растровый кэш вводить только по замеру. Длинный список геометрии можно кэшировать как ui.Picture с явным dispose, если это понадобится.

## Риски и ограничения

- Это ручные метки, не net diff. «Добавил и стёр» оставляет красное назначение. Удалить действие можно через undo.
- Серверный PNG включает ручные мазки; из него нельзя восстановить автоматическую маску до правок.
- После undo применённого мазка база может временно содержать его эффект до пересчёта. Мгновенное восстановление автоматической базы потребовало бы отдельного контракта.
- Не обещать совпадение AA-кромки Flutter/браузера с OpenCV LINE_8; проверять внутренние области и размеры.
- RGBA-буфер требует width×height×4 байт. Избегать лишних копий и неограниченного кэша; измерить длинную страницу и сотни мазков.
- Легенда объясняет палитру; одна красно-зелёная пара недостаточна для доступности.
- В рабочей папке есть другие изменения, включая 049: накладывать минимальный diff на актуальные файлы.
