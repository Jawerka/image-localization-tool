# Validation guide

Проверки выполняются после реализации. Автоматические проверки пройдены; ручная приёмка ниже ещё не отмечена.

## Подготовка

- Окружение проекта Python и desktop Flutter согласно текущей документации.
- Тестовый проект с готовой маской, содержащей области 0 и 255, и копия страницы без рассчитанной маски.
- Синтетические растровые fixtures для проверки цветов на белом и тёмном фоне.

## Автоматические проверки

Из корня проекта:

```powershell
Set-Location apps/desktop
flutter analyze
flutter test test/mask_overlay_painter_test.dart test/viewer_state_test.dart test/viewer_widget_test.dart
Set-Location ../..
npm run test:js
```

`mask_overlay_painter_test.dart` и `test_mask_overlay.mjs` созданы при реализации.
Композиция и состояния проверяются по [UI-контракту](contracts/mask-overlay.md).

## Ручная приёмка в desktop и браузере

1. Открыть готовую страницу: при отсутствии strokes вид маски прежний.
2. Кистью пройти через затемнённую и прозрачную части: весь след зелёный 50%.
3. Ластиком пройти через обе части: весь след красный 50%.
4. Пересечь красный зелёным и наоборот: последний цвет побеждает без потемнения.
5. Повторить точкой и заливками; проверить край страницы.
6. Undo/redo: вернуть предыдущий цвет и восстановить новый.
7. Отменить незавершённый жест/контур: временный след исчезает.
8. Сбросить черновик: сохранённые метки остаются, новые исчезают.
9. Нажать «Готово», дождаться результата: цвет не исчезает.
10. Перейти на другую страницу, вернуться, перезапустить: сохранённые цвета восстановлены.
11. Отключить/включить слой, менять zoom/pan и три режима просмотра: совпадение геометрии и единая видимость.
12. На странице без mask показать ручные следы без чёрного фона.
13. Имитировать медленную загрузку и быстро переключать страницы: чужой слой не появляется.
14. При ошибке сохранения черновик и его цвет остаются, ошибка видна.
15. Экспортировать один документ с включённым/выключенным слоем: файлы изображения одинаковы.

Браузерный запуск: `python -m src.app --browser`. Для desktop использовать текущий способ запуска из `apps/desktop/README.md`.

## Производительность

На одной и той же длинной странице сравнить исходную версию и реализацию: движение кисти, zoom/pan, сотни мазков. Зафиксировать размеры страницы, число мазков, время кадра и память. Проверить отсутствие полной конвертации mask на каждом pointermove и освобождение буферов при смене страницы.

## Ограничение при undo применённой правки

Цветные метки должны следовать документу сразу. Базовая серверная маска может ждать пересчёта; после его завершения слой должен обновиться. Не принимать старую картинку за подтверждение нового результата.
