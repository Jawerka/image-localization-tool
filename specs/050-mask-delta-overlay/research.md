# Research: Цвет ручных правок маски

Дата: 2026-10-20. Исследован локальный код, включая незакоммиченные изменения 049. Внешние библиотеки и новые API не выбирались.

## Решение 1 — Показывать ручные назначения

**Decision**: Цвет всего следа последнего ручного действия, включая повторное назначение.
**Rationale**: Соответствует примерам пользователя и позволяет видеть исключение даже на пустой маске.
**Alternatives**: Строгая разница baseline/current не показывает операции без изменения значения и убирает цвет после обратной операции. Это другой продуктовый смысл.

## Решение 2 — Использовать существующие strokes

**Decision**: Восстанавливать постоянные цвета из упорядоченного `document.strokes`.
**Rationale**: Данные уже сохраняются, участвуют в undo/redo и присутствуют в обоих интерфейсах. Серверная маска уже включает их эффект.
**Alternatives**: Отдельный цветной PNG потребовал бы синхронизации/хранения; отдельная история цветов дублировала бы историю документа. Baseline не нужен для меток назначений.

## Решение 3 — Один слой, opacity 0.5

**Decision**: Чёрная inverse-alpha база плюс непрозрачные цветные следы; обычное смешивание всего слоя на 50%.
**Rationale**: Заменяет чёрный цвет внутри мазка, не накапливает непрозрачность на пересечениях.
**Alternatives**: Цвет поверх текущего multiply-затемнения даёт грязные цвета; полупрозрачность каждого мазка отдельно усиливает пересечения.

## Решение 4 — Постоянство после сохранения

**Decision**: Сохранять цвета после «Готово» и открытия проекта.
**Rationale**: Значение цвета — ручное назначение, а не статус несохранённой правки. Не требуется отдельная точка отсчёта.
**Alternatives**: Только неприменённые мазки потребовали бы baseline/prefix и дали бы исчезновение цвета после сохранения.

## Решение 5 — Геометрия и ограничения

**Decision**: Повторно использовать геометрию текущих инструментов; проверять raster-composition на синтетических масках.
**Rationale**: Сервер использует OpenCV LINE_8, UI — сглаживание Canvas. Различие на кромке допустимо; внутренние области должны соответствовать контракту.
**Alternatives**: Новый серверный цветной endpoint дал бы более точную геометрию, но ухудшил бы локальный предпросмотр и увеличил scope.
