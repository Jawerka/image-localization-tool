# Plan: Измерение времени и памяти

## Approach

1. Вернуть отдельные timings стадий из `PagePipeline.rerender`.
2. Расширить `scripts/eval_pipeline.py`: повторы одной страницы на одном pipeline, cold/warm label, I/O, размеры файлов и RSS выборку через необязательный psutil.
3. Передавать вычисленное очередью время ожидания только в runtime-сообщении воркеру; не сохранять монотонные метки в persisted queue.
4. Добавить `X-Preview-Duration-Ms` к ответу preview.
5. Зафиксировать контракты тестами и выполнить rerender по сохранённым OCR/переводам, затем сравнить пиксели и метрики.

## Decisions

- Время измеряется монотонными часами, RSS — выборками текущего процесса с интервалом 20 ms.
- psutil необязателен для запуска приложения; если он недоступен в eval-среде, поля памяти остаются `null` с пояснением.
- Первый вызов каждой страницы внутри процесса маркируется `cold`, последующие повторы — `warm`; это прогретость процесса/объектов pipeline, не утверждение о холодном файловом кэше ОС.
- Preview latency передаётся заголовком, чтобы не менять PNG bytes и существующий response body.
