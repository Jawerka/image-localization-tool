# Feature Specification: Надёжная докачка компонентов

**Feature Branch**: `033-reliable-component-delivery`
**Created**: 2026-10-14
**Status**: Accepted for implementation
**Input**: Подготовить проект по `docs/DOWNLOAD_DELIVERY_PLAN.md` и приложенному пользователем плану.

## User Scenarios & Testing

### User Story 1 — Подготовка приложения (Priority: P1)

Пользователь выбирает способ перевода и языки, видит общий объём и нажимает «Подготовить приложение». Не устанавливает инструменты разработки и не настраивает CUDA. Основные веса и дополнительные компоненты отсутствуют в базовой сборке.

**Why this priority**: это основной путь первого запуска.
**Independent Test**: чистая сборка готовит выбранное направление и обрабатывает страницу; после подготовки тот же сценарий работает без сети.
**Acceptance Scenarios**:
1. При отсутствии компонентов одна подготовка устанавливает полный набор, включая OCR и языковой пакет оффлайн-перевода.
2. На NVIDIA приложение рекомендует совместимое ускорение; пользователь может выбрать меньшую загрузку CPU.
3. Подготовленные компоненты не скачиваются повторно при запуске или обновлении приложения с тем же набором.

### User Story 2 — Продолжение после сбоя (Priority: P1)

Пользователь сохраняет прогресс после обрыва сети или закрытия приложения, продолжает одной кнопкой. Ошибка объясняется понятной причиной.

**Why this priority**: потеря гигабайтов загрузки недопустима.
**Independent Test**: локальный сервер воспроизводит обрыв, игнорирование диапазона, повреждение, 429 и 503.
**Acceptance Scenarios**:
1. Проверенные файлы сохраняются, незавершённый продолжается при поддержке сервера.
2. Временный сбой повторяется автоматически ограниченное число раз; повреждённый файл никогда не активируется.
3. Пауза/перезапуск сохраняют очередь; интерфейс восстанавливает состояние независимо от пропущенных событий.

### User Story 3 — Безопасное восстановление (Priority: P1)

При нехватке места, ошибке установки или несовместимости сохраняется работоспособная версия и доступен повтор либо CPU.

**Why this priority**: подготовка не должна ломать установленное приложение.
**Independent Test**: остановка на установке и проверке, блокировка DLL, два процесса, неверный состав.
**Acceptance Scenarios**:
1. Готовность подтверждается проверкой компонента, а не наличием одного непустого файла.
2. Установка новой ревизии не изменяет текущую до успешной проверки.
3. Два процесса не пишут одновременно; скачивание и распаковка проверяют свободное место и доступ.

### User Story 4 — Простой выпуск (Priority: P2)

Разработчик подготавливает релиз одним действием и публикует протестированные файлы другим, после ручной проверки.

**Why this priority**: уменьшает ручные ошибки и стоимость каждого выпуска.
**Independent Test**: подготовка читает фиксированный каталог, не меняет локи; публикация отвергает изменение одобренных файлов.
**Acceptance Scenarios**:
1. Обычный выпуск не подбирает версии зависимостей заново.
2. Встроенный и выпускаемый каталоги совпадают; зависимость доступна анонимно до публикации приложения.
3. Повтор действия не требует повторной генерации тяжёлых пакетов и не перезаписывает опубликованный релиз другим содержимым.

### Edge Cases

Нет сети; 200 вместо продолжения; неверный диапазон/416; 429/5xx; усечённое тело; повреждение кэша; исчезнувший источник; отсутствие места; недоступный каталог; параллельные процессы; завершение при переключении; несовместимый GPU; неподдерживаемое языковое направление; старые установленные компоненты; отсутствие прав на портативную папку.

## Requirements

### Functional Requirements

- **FR-001**: Фиксированный каталог содержит точные версии, платформу, совместимость, зависимости, размеры, контрольные суммы и источники; обновляется отдельно от приложения.
- **FR-002**: Приложение устанавливает компоненты по встроенному каталогу без публикации своей версии и без инструментов разработки на машине пользователя.
- **FR-003**: Загрузки используют общий постоянный кэш, проверяют целостность и сохраняют подтверждённые файлы и незавершённые загрузки при сбое.
- **FR-004**: Продолжение учитывает фактический ответ сервера, автоматически повторяет временные ошибки и использует только проверенные резервные источники.
- **FR-005**: Очередь и прогресс сохраняются; доступны пауза и продолжение после запуска.
- **FR-006**: Установка сериализована между процессами, проверяет место/доступ и не активирует неполную ревизию.
- **FR-007**: Новая ревизия проверяется до переключения; старая сохраняется при отказе; runtime переключается через новый процесс.
- **FR-008**: Обычная установка использует доступную пользователю папку данных; portable и сервер поддерживают явный корень; прежние данные читаются без скрытой перекачки.
- **FR-009**: База не содержит PyTorch, Argos и основных весов, включая RapidOCR; остаются ресурсы запуска и один небольшой базовый шрифт с кириллицей.
- **FR-010**: Языковые пакеты устанавливаются при подготовке, обработка страниц не выполняет скрытых загрузок.
- **FR-011**: Мастер определяет полный набор из выбранного режима и языков, показывает суммарный объём и одно действие подготовки.
- **FR-012**: Выбор GPU подтверждается работой компонента; CPU доступен с понятным объёмом, без молчаливой дополнительной загрузки.
- **FR-013**: Поддерживается cu130 для совместимой NVIDIA на Windows и сохраняются cu128/CPU; сервер выбирает поддерживаемый платформой вариант.
- **FR-014**: Подготовка релиза автоматизирует обе платформы, проверки, расширения и draft; публикация не пересобирает файлы и проверяет анонимную доступность компонентов.
- **FR-015**: Тесты воспроизводят сетевые/установочные сбои локально; чистые frozen-сборки проверяются отдельно, ручная приёмка и публикация не объявляются выполненными без доказательства.
- **FR-016**: Кэш очищается по ограниченной политике без удаления активных загрузок и компонентов; диагностика не содержит секретов.
- **FR-017**: Пайплайн v2, CLI, окно, расширение и LAN сохраняют совместимость.

### Key Entities

- Компонент: назначение, ревизия, совместимость, состав и проверка готовности.
- Артефакт: неизменяемое содержимое, размер, происхождение, контрольная сумма и источники.
- Задача подготовки: выбранный набор, этап, сохранённый прогресс, причина остановки.
- Релиз-кандидат: исходная версия, комплект файлов, доказательства проверки и контрольные суммы.

## Success Criteria

### Measurable Outcomes

- **SC-001**: После выбора режима и языков подготовка запускается одним действием; ручная установка внешних инструментов не требуется.
- **SC-002**: Проверенные артефакты не передаются повторно после обрыва; частичный файл продолжается при поддержке источником.
- **SC-003**: Все перечисленные локально воспроизводимые сбои оставляют целостную активную установку и доступное восстановление.
- **SC-004**: Повторный запуск подготовленного сценария без сети не требует загрузок.
- **SC-005**: Обычный выпуск выполняется подготовкой и публикацией после ручной проверки, без изменения набора зависимостей и повторной генерации тяжёлых сводок.

## Assumptions

- Независимое зеркало не разворачивается в этой фиче; резервные источники используются только при наличии проверенной копии.
- Сохраняется версия приложения 1.0.1 до решения о публикации; компоненты имеют отдельную идентичность.
- Один базовый кириллический шрифт остаётся внутри; инструменты загрузки и запуска не выносятся.
- Предпочтительное направление оффлайн-перевода en→ru включается первым; другие доступные направления должны иметь зафиксированные записи либо понятное сообщение, без скрытого подбора при переводе.
- Эта фича заменяет требование 032 об удалении всех `.part` при ошибке сохранением проверяемого кэша; незавершённые установки по-прежнему не активируются.
- Автоматические тесты обязательны для восстановления и целостности; реальный Windows/GPU/Linux smoke фиксируется отдельно от модульных проверок.
