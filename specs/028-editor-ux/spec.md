# Feature Specification: Editor UX — док, очередь, статусы, поля, превью

**Feature Branch**: `028-editor-ux`

**Created**: 2026-10-11

**Status**: Implemented

**Input**: Пользовательский список улучшений редактора после 027: перетаскиваемый док (сверху/снизу) с сохранением позиции; прогресс-бар в строке страницы; блок «Пакетный прогон» → «Очередь» с иконочными кнопками паузы и стопа; при правке перевода статус страницы сбрасывался на «не начата» (должен быть «в обработке»); «Перевести» должен реагировать мгновенно, а не через секунды; поиск −10 px и «Добавить регион» −8 px, все однострочные поля — одной высоты (~32 px); превью страниц ×1.3; у канваса вертикальный запас ~¼ листа для навигации; «Перевести всё» убрать из рельса в меню кнопки «Перевести».

## Research: почему статус сбрасывался на «не начата»

Причина найдена без правок Python. Воркер шлёт `job.progress` c payload: `progress`, `stage` (код этапа) и **`status`** — человекочитаемую стадию пайплайна («Маска букв», «Вёрстка», …), см. `_progress()` в `src/app/worker.py:1306`. Десктоп обрабатывал это событие через `_mergePage(data)` (`workspace_state.dart`), и `PageRow.merge` нормализовал поле `status` через `normalizePageStatus()`: строка «Маска букв» не входит в словарь → `idle` → «не начата», при этом `progress` и `stage` жили. Веб (`web/js/main.js:onProgress`) payload.status не читает: ставит `status: "running"`, переносит `progress`/`stage`, чистит `error`. Фикс — отдельный `_mergeProgress()` в десктопе (паритет с вебом). Python-пайплайн, API и воркер не меняются.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Перетаскиваемый док (Priority: P1)

Пользователь тянет док канваса за ручку: док следует за указателем; отпускание дальше ⅓ высоты сцены переносит его к верхнему (12 px) или нижнему (16 px) краю. Позиция сохраняется в настройках и восстанавливается после перезапуска.

**Why this priority**: заявленная пользователем навигация: при высоком листе док снизу мешает нижним регионам, и наоборот.

**Independent Test**: виджет-тест: drag ручки `viewer-dock-grip` вверх > ⅓ → `workspace.dockAtTop == true` и `PUT /api/settings {"dock_position":"top"}`; drag вниз → обратно. Юнит-тест `AppSettings`: `dock_position` нормализуется, пишется в `to_dict`, читается `from_dict`.

**Acceptance Scenarios**:

1. **Given** открытая страница, **When** док тянется вверх больше ⅓ высоты сцены, **Then** док встаёт у верхнего края (12 px), `dockAtTop` = true, уходит `PUT` с `dock_position: "top"`.
2. **Given** док сверху, **When** тянется вниз больше ⅓, **Then** док возвращается к нижнему краю (16 px), `dock_position: "bottom"`.
3. **Given** сдвиг меньше ⅓, **Then** док возвращается на исходную сторону, PUT не уходит.
4. **Given** перезапуск/bootstrap с `dock_position: "top"`, **Then** док отрисован у верхнего края.

### User Story 2 - Статус «в обработке» при правках и вёрстке (Priority: P1)

Во время перевёрстки после правки перевода (и в любой обработке) строка страницы показывает «идёт N % · Вёрстка», точку/полоску активности — и не сбрасывается на «не начата».

**Why this priority**: сейчас событие `job.progress` затирает статус строки в `idle`; пользователь теряет понимание процесса.

**Independent Test**: юнит-тест `workspace_state`: `job.progress` с `status: 'Маска букв'` → `pages.single.status == 'running'`, `progress`/`stage` перенесены, `error` пуст; `page.updated` по-прежнему меняет статус на серверный.

**Acceptance Scenarios**:

1. **Given** страница `edited`, **When** приходит `job.progress` (percent 65, stage `typeset`, status «Вёрстка»), **Then** строка — `running`, «идёт 65 % · Вёрстка», виден прогресс-бар.
2. **Given** `job.progress` без `page_id`, **Then** ни одна строка не меняется.
3. **Given** после завершения приходит `page.updated` (`done`/`edited`), **Then** строка снова показывает итоговый статус (поведение не изменилось).

---

### User Story 3 - Мгновенная реакция «Перевести» (Priority: P1)

Нажатие «Перевести» (страница), пункта «Перевести всё» или Ctrl+Enter/Ctrl+Shift+Enter сразу ставит страницы в «в очереди»: видна пилюля задачи, блок «Очередь», строки получают статус; POST уходит следом. Если POST не удался — состояние откатывается, ошибка видна пользователю.

**Why this priority**: сейчас после нажатия несколько секунд «ничего не происходит» — выглядит как зависание.

**Independent Test**: юнит-тест `workspace_state`: `translate()` помечает `queued` синхронно (до завершения POST), тело содержит `scope:"all"` и `skip_ready:true`; при ошибке POST статусы строк возвращаются. Виджет-тест: tap `top-translate` → после одного `pump` строка уже «в очереди»; Ctrl+Enter шлёт POST `scope:"page"`, Ctrl+Shift+Enter — `scope:"all"`.

**Acceptance Scenarios**:

1. **Given** страница `done`, **When** «Перевести» (кнопка/меню/Ctrl+Enter), **Then** сразу появляется очередь, затем POST `{"scope":"page","page_id":…}`.
2. **Given** проект с готовыми и неготовыми страницами, **When** «Перевести всё», **Then** `skip_ready:true`, в «в очереди» только неготовые, готовые не переделываются.
3. **Given** сервер вернул ошибку POST, **Then** строки возвращаются к прежним статусам, полоса ошибки показывает причину.
4. **Given** фокус в поле ввода, **When** Ctrl+Enter, **Then** хоткей не срабатывает (символ идёт в поле).

---

### User Story 4 - Блок «Очередь» (Priority: P2)

Заголовок блока — «Очередь» / «Очередь на паузе», иконка `playlist_play`; кнопки без подписей с тултипами: пауза/продолжение (`pause`/`play_arrow`), стоп (`stop`, квадрат, красный акцент).

**Independent Test**: виджет-тест: `pages-batch` содержит текст «Очередь», кнопки `batch-pause`/`batch-stop` без текста, с иконками; при `paused` иконка паузы меняется на `play_arrow`.

**Acceptance Scenarios**:

1. **Given** идёт прогон, **Then** заголовок «Очередь», видны иконочные пауза и стоп.
2. **Given** пауза, **Then** «Очередь на паузе», кнопка продолжения — `play_arrow`.

---

### User Story 5 - Прогресс-бар в строке страницы (Priority: P2)

У `running`-страницы в левом рельсе видна полоска прогресса 4 px со скруглением, цвета `primary`, под статусом; во время вёрстки после правок — тоже.

**Independent Test**: виджет-тест: при `job.progress` у строки есть `LinearProgressIndicator` высотой 4 при `value ≈ 0.65`.

**Acceptance Scenarios**:

1. **Given** `job.progress` 65 %, **Then** в строке полоска 4 px заполнена на 65 %.
2. **Given** страница не running, **Then** полоски нет.

---

### User Story 6 - Высоты контролов (Priority: P2)

Поиск по страницам — 32 px; все однострочные поля (настройки, инспектор, глоссарий, поиск F1, поле API-ключа, hex-поля стиля, поля экспорта) — 32 px; «Добавить регион» — 48 px. Многострочные поля «Перевод»/«Оригинал» не меняются.

**Independent Test**: виджет-тесты: `pages-search` = 32, `inspector-add-region` = 48; проверка `IltTextField`/`InspectorInput` (однострочный) = 32, многострочный — больше.

**Acceptance Scenarios**:

1. **Given** редактор, **Then** поиск и все однострочные поля — ровно 32 px, текст центрирован.
2. **Given** вкладка «Текст» с документом, **Then** «Добавить регион» — 48 px.
3. **Given** многострочный «Перевод», **Then** высота от `minLines`, не 32.

---

### User Story 7 - Превью ×1.3 (Priority: P3)

Миниатюры в левом рельсе — 55×75 (декод с запасом), строка списка — 83 px; макет `.prow__thumb` совпадает.

**Independent Test**: виджет-тест: `pages-thumb-{id}` = 55×75, строка `page-row-{id}` = 83.

**Acceptance Scenarios**:

1. **Given** строка страницы, **Then** миниатюра 55×75, статус-точка в углу, строка 83 px, клики/reorder работают.

---

### User Story 8 - Вертикальный запас канваса ¼ (Priority: P3)

Лист выше вьюпорта можно поднимать/опускать так, что над верхом и под низом появляется пустой запас ≈25 % высоты листа — край листа не «прилипает» к краю окна.

**Independent Test**: юнит-тесты `canvas_geometry`/`viewer_state`: `clamped(..., verticalMargin: 0.25)` допускает `ty` в `[vh − sh − 0.25·sh, +0.25·sh]`; `panBy` доезжает до границы запаса; по умолчанию (`verticalMargin: 0`) поведение прежнее (все старые тесты зелёные).

**Acceptance Scenarios**:

1. **Given** лист выше вьюпорта, **When** панорама вверх/вниз, **Then** доступен пустой запас ≈¼ высоты листа сверху и снизу, дальше не пускает.
2. **Given** лист меньше вьюпорта, **Then** он по-прежнему по центру (запас не мешает).

---

### User Story 9 - «Перевести всё» в меню «Перевести» (Priority: P3)

В подвале рельса остаются счётчики, прогресс, «N проблема» и «Повторить ошибки»; кнопки «Перевести всё» там нет. Пункт выпадающего меню кнопки «Перевести» называется «Перевести всё».

**Independent Test**: виджет-тест: `pages-translate-all` отсутствует; меню `top-translate-menu` содержит пункт «Перевести всё», выбор шлёт POST `scope:"all"`.

**Acceptance Scenarios**:

1. **Given** редактор, **Then** в подвале рельса нет кнопки «Перевести всё».
2. **Given** меню кнопки «Перевести», **Then** пункт «Перевести всё» переводит все неготовые страницы.

---

### Edge Cases

- Drag дока: отпускание ровно на пороге ⅓ (равенство) — сторона не меняется; drag с малым дрожанием не шлёт PUT.
- `dock_position` в bootstrap отсутствует/некорректен — дефолт `bottom`, ошибок нет.
- `job.progress` с нечисловым `progress` — прежнее значение строки не портится.
- Оптимистичный translate при `_busyAction` (другой запрос в полёте) — повторный POST не уходит; откат не затирает чужие изменения.
- Ctrl+Enter при открытом оверлее/первом запуске — не срабатывает (`enabled` guard).
- Ошибка PUT `dock_position` — позиция остаётся локальной (не критичная настройка), полоса ошибки не поднимается.
- Многострочные поля инспектора не должны быть зажаты в 32 px.
- Зум/пан с запасом: `fit` листа меньше вьюпорта по-прежнему центрирует; хит-тесты и координаты листа не меняются.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: `AppSettings` MUST хранить `dock_position` (`"top"`/`"bottom"`, дефолт `"bottom"`): нормализация, `to_dict`, `from_dict`; ключ попадает в bootstrap через общий `settings`.
- **FR-002**: `WorkspaceState` MUST отдавать `dockAtTop` и `setDockPosition(bool)`: оптимистично менять значение и локальные настройки, затем `PUT /api/settings`; ошибка PUT не поднимает полосу ошибок.
- **FR-003**: `ViewerDockHost` MUST давать ручку `viewer-dock-grip` (`Icons.drag_indicator`, курсор `grab`/`grabbing`), вести док за указателем и по отпусканию за порогом ⅓ высоты сцены переносить к верхнему (12 px) или нижнему (16 px) краю; док остаётся `viewer-dock`.
- **FR-004**: Событие `job.progress` MUST обновлять строку как веб: `status: "running"`, `progress` (или `percent`), `stage`, `error: ""`; `page.updated` MUST NOT менять семантику.
- **FR-005**: `WorkspaceState.translate()` MUST сначала пометить очередь (страница — всегда; «всё» — только `!isReady`), затем отправить POST; тело «всё» содержит `skip_ready: true`; при ошибке POST MUST откатывать список строк.
- **FR-006**: Прогресс-бар строки страницы MUST быть 4 px со скруглением 2 и цветом `primary`, виден при `running`.
- **FR-007**: Блок батча MUST называться «Очередь»/«Очередь на паузе» (иконка `playlist_play`); `batch-pause` MUST показывать `pause`/`play_arrow` без подписи (тултип), `batch-stop` — `stop` без подписи с красным акцентом (тултип).
- **FR-008**: Горячие клавиши MUST добавлять Ctrl+Enter (перевести текущую страницу) и Ctrl+Shift+Enter (перевести всё) под guard `enabled`/`_isTyping`; условия те же, что у кнопки (проект, не busy).
- **FR-009**: Высоты MUST быть: `pages-search` 32, однострочные `IltTextField`/`IltNumberField`/`IltSelect`/`InspectorInput`/поиск F1/поля глоссария/API-ключ/hex-поле стиля/поле пути экспорта — 32, кнопка «Добавить регион» — 48; многострочные «Перевод»/«Оригинал» не трогать. Общая константа `kFieldHeight = 32`.
- **FR-010**: Миниатюра `PageThumb` MUST быть 55×75 (декод `targetWidth` ≈110), строка страницы — 83 px; `.prow__thumb` в макетах — 55×75.
- **FR-011**: `ViewTransform.clamped(..., {double verticalMargin = 0})` MUST допускать пустой запас `verticalMargin × sh` сверху и снизу для листа выше вьюпорта; `CanvasSession` использует 0.25 в `_recompute`/`zoomStep`/`panBy`; дефолт 0 сохраняет прежнее поведение и хит-тесты.
- **FR-012**: Подвал рельса MUST NOT содержать `pages-translate-all`; пункт меню кнопки «Перевести» MUST называться «Перевести всё»; макеты `web/mockups/next` приводятся в соответствие (высоты, превью, «Очередь», иконочные кнопки, без кнопки в подвале).
- **FR-013**: Новые тесты: `job.progress` → `running`; оптимистичный `translate` + `skip_ready` + откат; `dock_position` (Dart + pytest); перетаскивание дока; высоты 32/48; превью 55×75/строка 83; вертикальный запас; Ctrl+Enter/Ctrl+Shift+Enter; отсутствие `pages-translate-all`. Регрессий pytest/Flutter-наборов нет.

### Key Entities

- **dock_position**: настройка `top|bottom` в `AppSettings`; Flutter читает из bootstrap, пишет PUT-ом.
- **ViewerDockHost**: обёртка дока с ручкой, drag-состоянием и снапом по порогу ⅓ высоты сцены.
- **PageRow.progress merge**: правило `job.progress` → `running` (паритет `onProgress` веба).
- **kFieldHeight**: единая высота однострочных полей (32) в `theme.dart`.
- **ViewTransform.verticalMargin**: доля высоты листа, доступная как пустой запас сверху/снизу.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Док переносится вверх/вниз drag-ом за ручку; позиция переживает перезапуск (`dock_position` в settings.json).
- **SC-002**: При перевёрстке после правки перевода строка показывает «идёт N % · этап» с полоской 4 px; «не начата» не появляется до реального сброса.
- **SC-003**: «Перевести»/Ctrl+Enter дают видимую реакцию (пилюля, «Очередь», «в очереди») в первом же кадре после нажатия.
- **SC-004**: Заголовок «Очередь», кнопки-иконки пауза/стоп с тултипами; в подвале нет «Перевести всё», пункт есть в меню.
- **SC-005**: `pages-search` и однострочные поля — 32 px, «Добавить регион» — 48 px; превью 55×75/строка 83; макеты не расходятся с Flutter.
- **SC-006**: Канвас допускает запас ¼ высоты листа сверху/снизу; старые тесты геометрии зелёные.
- **SC-007**: `flutter analyze` — 0 issues, `flutter test` и pytest зелёные.

## Assumptions

- Payload `job.progress` стабилен: `page_id`, `progress`, `stage`, `status` (человекочитаемая стадия) — фикс чисто клиентский, Python не меняется.
- Позиция дока — настройка UI: синхронизация с сервером через существующий `PUT /api/settings`, без миграций и схемных изменений (schema 1, ключ аддитивный).
- Порог перекидывания дока — ⅓ высоты сцены (спека плана); меньше порога — возврат на исходную сторону.
- Многострочные поля инспектора («Перевод», «Оригинал») вне правил высоты 32.
