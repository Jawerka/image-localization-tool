# Feature Specification: Профили первого запуска

**Feature Branch**: `044-first-run-profiles`
**Created**: 2026-10-18
**Status**: Ready
**Input**: Make first-run local/server/offline preparation clear, preserve the default fallback, and show resource volume before preparation.

## User Scenarios & Testing

### User Story 1 — Подготовить серверный LLM с локальным fallback (Priority: P1)
Пользователь указывает внешний совместимый LLM/VLM и до загрузки понимает, что очистка изображения и fallback всё равно требуют локальных компонентов.

**Independent Test**: Первый запуск строит план выбранных компонентов, показывает оставшиеся байты загрузки и место установки, затем готовит их существующим coordinator-ом.

**Acceptance Scenarios**:

1. **Given** выбран серверный LLM, **When** показан план, **Then** видны локальные компоненты и полное пространство до старта загрузки.
2. **Given** пользователь запускает подготовку, **When** она идёт, **Then** виден общий прогресс и состояние, а pause/resume сохраняется.

### User Story 2 — Выбрать офлайн-профиль (Priority: P2)
Пользователь выбирает офлайн распознавание и перевод и видит, поддерживается ли нужное направление перевода.

**Independent Test**: Для существующего Argos-направления план включает соответствующий ресурс; для отсутствующего направления мастер показывает причину и не запускает скрытое скачивание.

**Acceptance Scenarios**:

1. **Given** направление есть в каталоге, **When** выбран офлайн-профиль, **Then** план содержит RapidOCR, локальную очистку и языковой ресурс.
2. **Given** направления нет, **When** выбран офлайн-профиль, **Then** пользователь получает явное сообщение о недоступном направлении и может вернуться к серверному LLM.

## Edge Cases

- Сумма загрузки равна нулю, потому что компоненты уже готовы: кнопка подготовки не запускает пустой download.
- Сервер LLM не указан: полный offline fallback остаётся предложенным по умолчанию.
- Подготовка прерывается: текущий coordinator сохраняет pause/resume и проверку целостности.
- Текущий API не поддерживает перенос всего пайплайна на удалённую машину; профиль сервера относится к LLM/VLM, локальная очистка остаётся локальной.

## Requirements

- **FR-001**: Мастер предлагает серверный LLM/VLM с локальным fallback и офлайн профиль.
- **FR-002**: До старта подготовки мастер показывает список компонентов, ожидаемые download bytes и required disk space.
- **FR-003**: Подготовка запускается существующим preparation coordinator-ом, не старым пофайловым model download циклом.
- **FR-004**: Мастер показывает downloading/installing/paused/ready/error прогресс и поддерживает продолжение после перезапуска.
- **FR-005**: Неподдерживаемый offline language pair не запускает подготовку и не меняет выбранные настройки.
- **FR-006**: По умолчанию выбирается полный fallback; выбор внешнего LLM не удаляет локальные OCR/cleanup fallback компоненты.
- **FR-007**: Интерфейс прямо сообщает, что серверный профиль обслуживает LLM/VLM, а inpainting и проекты остаются на локальном компьютере.

## Success Criteria

- **SC-001**: Пользователь видит download volume и required disk space до первого сетевого запроса.
- **SC-002**: Полный путь запускается через один preparation API start и сохраняет существующие pause/resume/integrity gates.
- **SC-003**: Offline profile only starts when a matching language component exists.
- **SC-004**: UI/API тесты проходят, а полный набор модели сохраняет существующий fallback по умолчанию.

## Assumptions

- Устанавливать компоненты следует через уже существующий preparation coordinator.
- Серверный профиль означает внешний OpenAI-compatible LLM/VLM, а не удалённый execution всего пайплайна.
- Локальные данные и ключ API не добавляются в отчёты или репозиторий.
