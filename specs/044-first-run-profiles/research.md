# Research: Профили первого запуска

## Решение: переиспользовать preparation coordinator

Сервер уже предоставляет plan/start/pause/resume/current для подготовки ресурсов, включая объём байтов и необходимое место на диске. UI использует эти endpoints. Старый пофайловый цикл моделей оставлен для экрана управления компонентами, но не участвует в новом сценарии подготовки мастера.

**Основание**: меньше дублирования загрузки, проверки целостности и восстановления после паузы; сохраняется существующий API жизненного цикла.

**Альтернатива**: отдельная загрузка моделей из мастера. Отклонена, поскольку дала бы второй путь установки и не имела бы coordinator-состояния.

## Решение: отделить endpoint LLM/VLM от локальных ресурсов

Серверный профиль задаёт перевод/VLM endpoint; OCR, очистка, fallback Argos и пользовательские проекты остаются локальными. Полный offline профиль доступен лишь при наличии выбранной Argos пары.

**Основание**: текущий API не исполняет весь pipeline удалённо. UI должен точно отражать фактический контракт.

**Альтернатива**: назвать режим просто «серверным переводом». Отклонена, так как может создать ложное впечатление о переносе очистки и файлов на сервер.

## Решение: загружать план до старта

Мастер показывает состав ресурсов, суммарный объём скачивания и место установки до вызова start. При ошибке построения плана ничего не запускается и настройки не перезаписываются.

**Основание**: пользователь видит цену загрузки и получает явный отказ для неподдерживаемой offline пары.

## Проверки, выполненные локально

- API plan и unsupported-offline: `3 passed`.
- Полный UI smoke набор с расширением в проектном venv после всех правок: `13 passed`, включая persisted error, pause/resume и жесты редактора.
- JavaScript suite: `50 passed`; полный Python suite до последнего JS-only Escape correction: `583 passed, 1 skipped`.
- Packaged Windows portable sidecar: два старта из отдельной чистой папки данных, оба bootstrap сохранили `first_run_complete=false`; временный профиль удалён. Это не проверяет real model preparation или translation.
- Повторная чистая portable-установка после исправления упаковщика: `dist/ImageLocalizationTool-1.0.2-windows-x64-portable.zip` извлечён во временный каталог, sidecar запущен с отдельным `ILT_DATA_DIR`, `/api/bootstrap` вернул `models_ready=false`, `first_run_complete=false`, подготовка `idle`; рядом с установкой `models/` содержит только `.keep`. ZIP — 108,392,242 байта, распакованная установка — 257,927,093 байта; вложенный RapidOCR asset сохранён. Первый запуск выявил, что `/XD` не удалял top-level `models`; `scripts/package-portable.ps1` теперь удаляет только `build/portable/ImageLocalizationTool/models` после копирования. Проверка архива подтвердила отсутствие моделей верхнего уровня и сохранение `sidecar/_internal/rapidocr/models`. Временные файлы проверки удалены после фиксации результата.
- На свежей portable-распаковке запущен сам `desktop/ImageLocalizationTool.exe` (Flutter host), который поднял bundled sidecar: `/api/bootstrap` доступен за 2,16 с, первый-run состояние осталось чистым (`models_ready=false`, `first_run_complete=false`, preparation `idle`). Это подтверждает запуск host и handshake, но скрин/взаимодействие с чистым окном не проверялись. Попытка включить WebView2 DevTools через `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` не открыла локальный `/json/version` endpoint за 45 секунд; временная установка и процессы удалены.
- Реальный план LLM + fallback для `en→ru`: загрузка 2,224,300,836 байт, требуемое место 6,231,769,888 байт. План получен без старта загрузки.
- `node --check web/js/settings.js` и `node --check web/js/api.js`: успешно.
- Системный Python не имеет Playwright; UI прогон выполнен через `venv`.
- Продолжение проверки 2026-10-18: full Python suite `607 passed, 1 skipped`; текущий UI smoke `14 passed`. Исправлен portable staging, чтобы чистый ZIP не нёс локальные модели; фактический first-run проверен отдельно, но реальная подготовка 2.22 GB runtime/Argos и восстановление приложения после перезапуска не запускались.

## Непроверенные пункты

- Чистая установка и первый настоящий перевод с загрузкой моделей требуют приёмки T18.
- Первый реальный перевод на чистом профиле не выполнялся; восстановление после перезапуска проверено unit/UI сценариями, но не через фактическое закрытие и повторный запуск установленного приложения.
