# Implementation Plan: Профили первого запуска

**Branch**: `044-first-run-profiles` | **Date**: 2026-10-18 | **Spec**: [spec.md](spec.md)

## Summary

Обновить мастер первого запуска: дать выбрать серверный OpenAI-совместимый LLM/VLM с полным локальным fallback или полностью офлайн-профиль; до загрузки показать состав компонентов, объём скачивания и требуемое место; подготовку проводить существующим coordinator-ом с восстановлением состояния.

## Technical Context

**Language/Version**: Python 3.10–3.13 (проектный диапазон), браузерный JavaScript ES modules  
**Primary Dependencies**: FastAPI, существующий preparation coordinator, WebView2/web UI  
**Storage**: существующий локальный Config и состояние preparation; новые сущности хранения не вводятся  
**Testing**: pytest API/UI tests, Node syntax check  
**Target Platform**: Windows desktop/WebView2 и браузерный интерфейс приложения  
**Project Type**: локальное desktop-приложение с web UI и HTTP API  
**Performance Goals**: показать план до сетевой загрузки; не ухудшить текущую последовательную установку и целостность компонентов  
**Constraints**: сервер LLM/VLM не запускает весь pipeline удалённо; OCR, inpainting и проекты остаются локальными. Ключ API не сохраняется в JSON или отчётах. Неподдерживаемый Argos language pair должен завершаться явной ошибкой.  
**Scale/Scope**: экран первого запуска, существующие endpoints подготовки, настройки профиля, API/UI проверки.

## Design

### Решения

1. UI обращается к существующим `/api/preparation/plan`, `/api/preparation/start`, `/api/preparation/pause`, `/api/preparation/resume` и `GET /api/preparation`, не реализуя отдельную загрузку моделей.
2. Профиль хранится как выбор мастера и применяется при сохранении настроек. Ошибка построения offline-плана не меняет сохранённую конфигурацию.
3. «Серверный» профиль означает только endpoint LLM/VLM; объём локальных компонентов остаётся виден и готовится локально.
4. План и текущее состояние coordinator-а — источники для оценки объёма, прогресса и восстановления после перезапуска.

### Основные части

- `web/index.html`, `web/js/settings.js`: варианты профиля, шаг языка, оценка/прогресс, pause/resume и пояснение границ серверного режима.
- `web/js/api.js`: вызовы существующего API подготовки.
- `src/app/preparation.py`, `src/app/server.py`: существующий coordinator/API; менять контракт только если тесты выявят недостающую информацию.
- `tests/unit/test_app_server.py`, `tests/e2e/test_ui_smoke.py`: проверка планирования и пользовательского выбора.

### Зависимости и поток

Выбор профиля и языка → POST plan → отображение компонентов/байтов/диска → один POST start → polling состояния → pause/resume или готовность → сохранение соответствующих настроек мастера.

### Риски

| Риск | Уровень | Смягчение |
|---|---|---|
| План выбранного языка устарел после смены профиля/языка | Средний | Перестраивать план по выбору и не разрешать переход до готового актуального плана |
| Сохранённый coordinator относится к другому выбору | Средний | Сопоставлять параметры текущего задания перед resume |
| Пользователь понимает endpoint как удалённое выполнение всего pipeline | Средний | Явно пояснить локальность OCR/inpainting и проектов в мастере |
| Playwright отсутствует в системном Python | Низкий | Запускать UI проверку проектным `venv` |
