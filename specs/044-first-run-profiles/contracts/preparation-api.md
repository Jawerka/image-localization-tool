# Контракт UI ↔ preparation API

Мастер использует существующий контракт приложения:

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/preparation/plan` | Рассчитать компоненты, download bytes, disk space и предупреждения для выбранных параметров |
| POST | `/api/preparation/start` | Запустить подготовку по выбранным параметрам |
| GET | `/api/preparation` | Получить текущее состояние и восстановить отображение после повторного открытия |
| POST | `/api/preparation/pause` | Приостановить активную подготовку |
| POST | `/api/preparation/resume` | Продолжить приостановленную подготовку |

Offline профиль отправляет `translator_backend: "argos"` и языковую пару. При неподдерживаемой паре plan возвращает явную ошибку; UI не вызывает start и не сохраняет новое значение backend. Профиль LLM/VLM отправляет `translator_backend: "llm"`; endpoint LLM/VLM настраивается отдельно и не меняет локальное размещение OCR/inpainting/проектов.
