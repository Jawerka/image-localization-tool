# Feature Specification: Безопасный деплой

**Feature Branch**: `codex/009-safe-deployment`
**Created**: 2026-11-04
**Status**: accepted (LAN CT113 и Windows fixture/dry run)
**Input**: Развернуть новый метод на сервере, исправить скрипт деплоя, внедрить dry run и обязательное правило его выполнения.

## User Scenarios & Testing

### User Story 1 — Предварительно проверить изменения (Priority: P1)

Пользователь видит проверенный план до записи файлов. План использует реальную цель и реальные артефакты, не ограничивается печатью команд.

**Independent Test**: Dry run не создаёт установку/резервные папки, не меняет её файлы и не перезапускает службу; при этом сообщает реальные изменения.

**Acceptance Scenarios**:
1. Given доступный сервер, When запущен dry run, Then проверены хеши, WorkingDirectory службы и место, без загрузки архива.
2. Given portable с пустыми пользовательскими каталогами, When выполнен Windows dry run, Then нет изменений установки.

### User Story 2 — Обновить только код с возможностью отката (Priority: P1)

**Independent Test**: Фиксированные пользовательские файлы сохраняются при замене кода; сбой health возвращает прежний код.

**Acceptance Scenarios**:
1. Given подготовленный план, When код сервера изменился до применения, Then обновление остановлено до остановки службы.
2. Given штатное обновление, When новая служба готова, Then хеши кода совпадают, настройки и проекты сохранены.
3. Given ошибка health, When выполняется откат, Then прежний код восстановлен и служба перезапущена.

### Edge Cases

Пути с traversal, симлинки, неправильный состав/хеш архива, неактивная или чужая служба, недостаточное место, пустые placeholder-папки, неизвестные файлы корня установки.

## Requirements

### Functional Requirements
- **FR-001**: Обязательный настоящий dry run до применения, в том числе при обычном запуске скрипта.
- **FR-002**: Не зеркалировать корень установки; изменять только разрешённые каталоги кода.
- **FR-003**: Сохранять актуальную резервную копию кода и data до записи.
- **FR-004**: LAN проверяет пути, ссылки, целостность архива, изменение сервера после плана и готовность службы; при сбое применения откатывает код.
- **FR-005**: Записать постоянное правило dry run перед каждым деплоем проекта.
- **FR-006**: Реально обновить CT113 указанным методом и проверить сохранность проектов/настроек.

## Success Criteria
- **SC-001**: Тесты dry run не обнаруживают записей в установку и перезапусков.
- **SC-002**: Windows-тесты с пустыми placeholder-папками сохраняют все пользовательские файлы и неизвестные файлы корня.
- **SC-003**: LAN-тесты проверяют отказ от устаревшего плана и откат после ошибки health.
- **SC-004**: После реального деплоя CT113 служба готова; конфигурация и 1460 файлов проектов совпадают с резервной копией.

## Assumptions

Изменение относительно 001 и 008. Публичный релиз, слияние и обновление других серверов не запрашивались. Наличие dry run не расширяет пользовательскую авторизацию. Физическая Windows-установка проверена только dry run; реальное копирование проверено на изолированных fixture.
