# 001. Текущее состояние Image Localization Tool

Дата среза: 2026-10-31. Эта спецификация описывает продукт таким, какой он есть в коде. Она заменяет накопленные спецификации 001–064: те лежат в `legacy/specs/` и в историю git не правятся.

Источник правды при расхождении — код. Расхождения старых текстов с кодом собраны в разделе «Известные расхождения», а не записаны здесь как требования.

Новая фича описывает только изменение относительно этого файла. Нумерация продолжается с 002. Статус `accepted` ставится после реального прогона на целевой поверхности; зелёные unit-тесты сами по себе статус не меняют.

## 1. Назначение и поверхности

Локальный перевод текста на изображениях: детекция областей, OCR, перевод, очистка букв, вёрстка перевода обратно в рисунок. Страница обрабатывается только через пайплайн v2 (`src/page_pipeline.py`). Новый путь распознавания, перевода или очистки не подменяет этот вход.

Поверхности, которые остаются на месте. Новая фича не убирает существующий вход и не меняет контракт соседней поверхности без отдельного требования.

| Поверхность | Как запускается |
|---|---|
| CLI | `python src/main.py` |
| Готовое окно | Flutter-хост `apps/desktop`, сайдкар `python -m src.app --api` |
| Окно из исходников | `python -m src.app` (pywebview + WebView2). Это путь разработки, не поставка |
| Браузер из исходников | `python -m src.app --browser` |
| Браузерный редактор | `python -m src.app --server`, Docker |
| LAN API | `python -m src.app --headless --remote` |
| Расширение | Chromium (заявлено) и Firefox (сборка есть, приёмка не заявлена), распакованное дополнение |
| Linux-служба | `deploy/ilt.service`, пользователь `ilt`, `--headless --remote` |

Заявленные ОС, форматы, языки, сеть и команды приёмки — в [docs/DISTRIBUTIONS.md](../../docs/DISTRIBUTIONS.md#матрица-поверхностей). Новая фича не убирает строку этой таблицы.

Флаги `python -m src.app`: `--server`, `--browser`, `--headless`, `--api`, `--parent-pid` (только с `--api`), `--remote`, `--deploy cpu|cuda|argos|models|all`. Повторный запуск окна передаёт пути уже открытому экземпляру. `--api` не пишет `instance.json`. `--component-check <path>` — отдельный вход проверки компонента, не флаг окна.

## 2. Пайплайн v2

Порядок: детектор → OCR → перевод → маска букв → очистка → вёрстка.

- Детектор по умолчанию — ogkalu RT-DETR-v2 ONNX. `orig_target_sizes` — `[ширина, высота]`.
- `detector_mode`: `ogkalu` (по умолчанию), `ctd`, `both`, `auto`. `auto` включает второй детектор (comic-text-detector) только при живой языковой модели. `ctd_conf` по умолчанию 0.4, диапазон 0.05–0.95. `ctd_seg_clip` по умолчанию выключен: обрезка маски обведённого звука картой второго детектора.
- OCR: `ocr_backend` `vlm` или `rapid`. VLM — vision-модель на OpenAI-совместимом сервере, длинная сторона страницы `vlm_max_side` (1536). Если сервер недоступен — RapidOCR и предупреждение. `min_confidence` (0.5) относится к RapidOCR.
- Перевод: `translator_backend` `llm` или `argos`. LLM обрабатывает запросы по одному. Пустой `llm_model` берётся из `/v1/models`. `llm_thinking` по умолчанию выключен. Фолбэк — Argos на целых блоках, офлайн только en↔ru. Неподдержанная офлайн-пара — ошибка «Это направление оффлайн-перевода пока не поддерживается».
- Очистка: `inpainter_backend` `lama` или `opencv`. Однородный фон заливается, остальное чистит LaMa. Если LaMa недоступна — предупреждение и переход на OpenCV. LaMa дорисовывает буквы, если кольцо однородности захватывает соседний текст.
- Порядок чтения: `reading_order` `auto`, `ltr` или `rtl`. `auto` решает VLM, геометрия — только фолбэк. Вертикальные колонки японского текста в эту схему не входят.
- Звуки: `sfx_mode` `replace` (по умолчанию, звуки переводятся) или `skip`. Устаревший флаг `translate_sfx: false` даёт `skip`. Явный `sfx_mode: null` в JSON тоже даёт `skip`.
- Оформление по исходным строкам: `adaptive_text` и `discover_missing_text` по умолчанию включены. Первый готовит геометрию (поворот по строкам, без постоянной дуги), второй делает дополнительный проход OCR пропущенных надписей. Ручные шрифт, интервалы, обводка, поворот, warp и положение не перезаписываются. При смене исходной рамки старая геометрия сбрасывается.
- Устройство: `device` `auto`, `gpu` или `cpu`. Без CUDA страница не обрывается: шаг уходит на CPU.
- Прозрачность PNG на выходе не сохраняется. Форматы страницы: PNG, JPG/JPEG, BMP, TIFF. Окно дополнительно открывает ZIP, CBZ, CBR, RAR, 7Z, TAR. Браузерный редактор — PNG/JPEG/BMP/TIFF, ZIP/CBZ и проекты `.ilt.zip`.

Ключ LLM уходит заголовком `Authorization: Bearer` и в `/v1/models`, и в `/v1/chat/completions`. Ответы 401 и 403 не повторяются: сразу включается RapidOCR + Argos. «Проверить» с заданным ключом шлёт ещё `chat/completions` с `max_tokens: 1`.

## 3. Редактор

Один проект на экземпляр. Очередь заданий, правка региона, стили и глоссарий живут в нём.

Левая панель — вкладки «Страницы» и «Очередь». Блок очереди виден только на своей вкладке. Во Flutter выбранная вкладка не сохраняется между запусками и не управляется стрелками.

Карточка региона — вкладки «Текст», «Шрифт», «Трансформация», не сворачиваемые секции. Повторный перевод ждёт сохранения текста и передаёт `base_version`.

Текст двигается отдельно от рамки и маски полем `text_position` (конечные координаты, не дальше ±1 000 000). `warp.version` — 1 или 2, по умолчанию 1; версия 2 — билинейные ячейки. Смена `text_position` требует только повторной вёрстки. `layout_snapshot` замораживает раскладку между предпросмотром и экспортом.

`POST /api/pages/{id}/preview-region` принимает `mode` из `exact`, `base-layer`, `base-page`, `base-overlay`, флаги `drafts_complete` и `apply_rotation`, заголовок `X-Layout-Snapshot`. Ответ — PNG с `X-Offset-X`, `X-Offset-Y`, `X-Preview-Revision`, `X-Preview-Mode`, `X-Preview-Duration-Ms`. Черновой предпросмотр сетки во время перетаскивания не ждёт сервер; точный кадр запрашивается после отпускания, с учётом revision. В вебе это WebGL по неизменной RGBA-текстуре (`web/js/mesh_preview_renderer.js`), без PixiJS.

Маска. Автоматическая маска букв расширяется на `letter_mask_grow_px` (1). Силуэт баллона и ручные штрихи не растут. Отступ ретуши от контура баллона внутрь — `bubble_mask_inset_px` (2). Поверх маски — чёрный негатив с прозрачностью 50%. Ручное добавление — `#90EE90`, вычитание — `#FF9999`, побеждает последнее действие. Слой правок не попадает в результат и экспорт. Скрытие маски прячет весь слой. Формат штриха и API маски этим не менялись.

Слои просмотрщика: `viewer_show_boxes` и `viewer_show_mask`, по умолчанию включены, пишутся в `data/settings.json` через `PUT /api/settings`. Во Flutter последний патч побеждает, запросы идут по одному, перед выходом запись дожидается. Web пишет те же ключи в существующие настройки.

Стили проекта копируются и вставляются (Ctrl+Shift+C / Ctrl+Shift+V). Глоссарий говорящих хранит оригинал, перевод, род и заметку внутри проекта. Это не память формулировок на серию.

Пакет проекта — `.ilt.zip` в окне и в браузере. Originals лежат в `data/imports`. Одноимённые архивы распаковываются в независимые пространства.

Горячие клавиши окна и браузерного редактора совпадают по действию. Одиночные клавиши инструментов включаются настройкой `single_key_shortcuts` и не срабатывают в текстовых полях.

## 4. Хранение данных

Всё пользовательское лежит в папке программы. `%APPDATA%` и `%LOCALAPPDATA%` не используются и не читаются для переноса. Старые данные оттуда копируются вручную.

| Что | Где |
|---|---|
| Настройки, проекты, журнал, подготовка | `data/` (`ILT_DATA_DIR` переопределяет) |
| Ключ LLM | `data/llm-api-key.txt`. `Config.save()` ключ в JSON не пишет. CLI читает флаг `--llm-api-key`, затем `ILT_LLM_API_KEY`, затем `llm_api_key` из файла |
| Журнал | `data/logs/app.log` у окна, `data/logs/cli.log` у CLI. Импорт `src/main.py` файл не создаёт. `--verbose` включает подробный вывод |
| Вход в браузерный редактор | `data/web-access.json`, пароль как хеш |
| Токен сопряжения расширения | `data/session.token` |
| Пакеты Argos | `data/argos-packages` |
| Кэш загрузок | `.downloads/` |
| Модели, шрифты, прочие компоненты | `models/`, `.resources/`, корень компонентов (`ILT_COMPONENT_ROOT` или `components_dir`) |
| Тяжёлые библиотеки | `runtime/` |

`config.json` CLI читает из текущего каталога или по `--config`. Команда его не создаёт. Неизвестные поля игнорируются. В репозиторий не попадают `models/`, `config.json`, `test-img/`, `data/`, `output/`, `.vendor/`, `legacy/`, `.downloads/`, `runtime/`, `.resources/`, `dist/`, логи и секреты.

## 5. Компоненты и подготовка

Два каталога.

- `src/app/runtime_manifest.json`, schema 2, `format: "wheels"`. Пакеты: `torch-cpu`, `torch-cu128` (драйвер от 570), `torch-cu130` (драйвер от 580), `argos`. У каждого файла адрес, размер и SHA-256. Источник — PyPI, PyTorch CDN или фиксированное колесо Argos. Генератор — `scripts/build_runtime_locks.py`, фиксированный каталог `locks/runtime-catalog.json`.
- `src/app/component_manifest.json`: детектор, LaMa, RapidOCR, языковые пары, шрифты, детектор звуков.

Раскладка пакета: `runtime/.revisions/<id>/<rev>/`, активная ревизия в `runtime/.active/`. Старый каталог `runtime/<id>/` только читается. Распаковка колёс пофайловая: путь не выходит из каталога, `.data/` пропускается, конфликт содержимого — ошибка. Повторный запуск ничего не перекачивает. `ILT_RUNTIME_MANIFEST_URL` подменяет каталог и проверяется строго. Фоновое обновление каталога по версии приложения не выполняется.

Порядок выбора torch: cpu < cu128 < cu130. `--deploy cuda` берёт cu130 или cu128 по `nvidia-smi`. Выбранный пакет запоминается. Устройство `auto` без CUDA уходит на CPU.

Подготовка — один координатор, состояние в `data/preparation.json`. После перезапуска активная подготовка становится `paused`.

- `GET /api/preparation`, `GET /api/preparation/diagnostics`
- `POST /api/preparation/plan|start|verify|pause|resume|location|cache/clear`
- `GET /api/runtime`, `POST /api/runtime/download` (202, либо 200 если уже стоит; 409 занято; 400 неизвестный id), `POST /api/runtime/remove` (409, пока идёт загрузка)
- События SSE `preparation.progress` и `runtime.progress`. В ответах bootstrap есть `runtime` и `preparation`.

План подготовки показывает объём скачивания, место установки и предупреждения до старта. Профили первого запуска: локальная модель, свой сервер LLM, офлайн. Офлайн — только en↔ru. `--deploy all` готовит набор Argos en→ru и не качает модели во время перевода.

## 6. Поставка и обновление

Windows — только portable ZIP, без `setup.exe`.

- Полный CPU-пакет содержит модели и зависимости. Обновление: закрыть приложение, сохранить папку, распаковать новую версию по прежнему пути, перенести только `data`.
- Лёгкий ZIP качает компоненты при подготовке. Обновление — `scripts/update-windows.ps1`: новая версия включается после проверки, откат возвращает предыдущую. Пользовательские каталоги сохраняются в обе стороны. К полному пакету этот скрипт не применяется.

Docker: образ `ghcr.io/jawerka/image-localization-tool:<version>-cpu-full`, канал разработки `edge-cpu-full` публикуется на каждый push в `main` после реальной обработки с `--network none`. Данные — в именованном volume. `docker compose down` данные сохраняет, `down -v` удаляет. Образ не откатывает изменения данных.

Linux-служба: `/opt/image-localization-tool`, `releases/<ver>`, ссылки `current` и `previous`, общие `shared/data`, `shared/models`, `shared/runtime`. Обновление включает версию только после `GET http://127.0.0.1:8765/v1/health` с `ready: true` (таймаут 60 с). Неудача возвращает `previous`. `--deploy all` — только при первой установке. Lock один на установку.

Выпуск: `scripts/release.ps1 -Prepare` гоняет Linux CI и Docker CI на одном коммите, кладёт полный Windows ZIP и Docker ZIP в кандидат и требует digest. Выпуск без Docker-пакета отклоняется. Тег `cpu-full` обновляется после стабильного GitHub Release. Заметки к версии читаются из `docs/RELEASE_NOTES_<ver>.md` до сборки.

## 7. Расширение браузера

Одна кнопка над изображением при наведении. Она показывает очередь, этап и ошибку. Готовый перевод подменяет картинку или ложится поверх, не меняя `src` и `srcset`. Повторное наведение открывает мини-панель: «Сравнить», «Копировать», «Перевести заново», «Убрать», «Не показывать на этом сайте», «Повторить», «Сохранить логи». Alt включает сравнение.

Порядок углов: правый верхний, левый верхний, правый нижний, левый нижний, отступ 6 px. Кнопка живёт в своём слое и переносится в открытый `dialog` и в полноэкранный режим. Привязка — CSS anchor с запасными координатами. Родитель картинки не меняется, сдвига вёрстки нет. События без `isTrusted` игнорируются.

Контекстное меню передаёт адрес картинки. Ручной выбор берёт `currentSrc`, холст и одиночный фон, только в верхнем фрейме, и закрывается по Escape. Сайты из `hoverDisabledSites` кнопку не показывают. Доступ ко всем сайтам запрашивается один раз при установке.

Задач одновременно не больше двух. Незавершённые с серверным id лежат в `storage.session` (`iltJobs`) и восстанавливаются. Результаты — в `CacheStorage` `ilt-results`, потолок 300 МБ. Журнал — до 2000 записей. Бейдж показывает число задач или ошибку.

Настройки: `buttonEnabled` (включено), `hoverDelayMs` 220, `hoverMinLong` 160 (короткая сторона не меньше 80), `theme` `system`, `chimeOnReady` выключен, `logVerbose` выключен.

Сервер: `GET /v1/jobs/{id}` отдаёт `label`, `elapsed_ms`, `eta_ms` (среднее по последним 20). `POST /v1/translate` принимает `fresh`.

Firefox собирается, живое поведение на Firefox не обещано. Режима совместимости, боковой панели и отдельной вкладки-фолбэка нет.

## 8. Доступ и безопасность

Браузерный редактор по умолчанию открыт. Вход включается явно: логин и пароль владельца (10–256 символов) в `data/web-access.json`. Сессия — HttpOnly cookie на 12 часов, сбрасывается при смене защиты и перезапуске. Это одна учётная запись на экземпляр, не пользователи с проектами. Приложение не читает `web.token` и `ILT_WEB_TOKEN`.

Локальный интерфейс слушает `127.0.0.1`. `--server` публикует адрес через `ILT_WEB_BIND` (в Compose по умолчанию только localhost) и проверяет точный список `ILT_WEB_ORIGINS`. `X-Forwarded-*` не доверяется. Чужой Host или Origin отклоняется.

Сопряжение расширения: код из 6 цифр на `127.0.0.1:8766`, затем `POST /v1/pair` и Bearer-токен устройству. LAN API по умолчанию `0.0.0.0:8765`, обычный HTTP без TLS. Трафик в недоверенной сети требует HTTPS на обратном прокси.

Браузерный редактор не открывает системные диалоги, не принимает произвольные серверные пути и не ставит runtime-пакеты. Предел одного файла — 256 МиБ. ZIP — до 10 000 записей и 2 ГиБ распакованного содержимого.

## 9. Заявленное качество

Ink recall 99.8–100% относится только к локальным эталонным страницам из `docs/BENCHMARK_RESULTS.md`. Это не качество на произвольной странице. Узкие баллоны переносятся по слогам. Текст на скринтоне чистится хуже ровного баллона. Звуки на пересечении с рисунком могут оставить исходные буквы.

## 10. Известные расхождения

Код расходится с текстами, которые раньше считались требованиями. Пока это не исправлено отдельной фичей, действует код.

- Если заняты все четыре угла, кнопка остаётся в правом верхнем углу видимой картинки. Поиска наименее перекрытого угла нет.

## 11. Технический долг

Зафиксировано, не запланировано. Закрытие пункта — отдельная фича или обычная правка, после которой строка отсюда убирается.

Высокий:

- `src/app/server.py` совмещает HTTP, проекты, очередь, превью и вёрстку. `src/app/worker.py` совмещает процессы, задания и восстановление статусов.
- Значения настроек по умолчанию повторены в `Config`, в полях `AppSettings` и в фолбэках нормализации. Новое поле правится в нескольких местах.
- После сплющивания истории `main` несжатые объекты исходников и полных результатов примеров в опубликованном git отсутствуют. В индексе остаются превью, `regions/` и `runs/`; `sources/`, `translated/` и `comparisons/*-full.jpg` локальные. Старые SHA измерений в `docs/examples/runs/` не подменять.

Средний:

- `src/app/component_catalog` импортируется из `src/utils/paths.py`, `src/components/rapid_ocr.py`, `src/components/font_catalog.py` и `src/components/translator.py`.
- `src/components/typesetter.py`, `web/js/viewer.js`, `web/js/inspector.js` и `apps/desktop/lib/src/state/viewer_state.dart` совмещают несколько задач и плохо делятся.

## 12. Как писать следующие спецификации

- Номер берёт Spec Kit: максимум по папкам `specs/` и по именам веток плюс один. После этой спецификации следующий номер — 002. Ветки `063-*` и `064-*` удалены, чтобы не занимать номер.
- Спецификация описывает изменение относительно этого файла: что добавляется, что перестаёт быть правдой, какой раздел 001 она заменяет. Повторять устройство продукта целиком не нужно.
- План, задачи и контракт живут в папке фичи. В 001 они не переносятся.
- Когда фича принята, изменившиеся правила дописываются в этот файл, а папка фичи уходит в `legacy/specs/`. Пока этого не сделано, 001 отстаёт от кода и подлежит правке в том же изменении.
- Исключение из конституции записывается в плане фичи, а не подразумевается.
