# Implementation Plan: Автоматическая разметка для ретуши

**Branch**: `codex/002-automatic-retouch` | **Date**: 2026-11-01 | **Spec**: [spec.md](spec.md)

## Summary

Дополнить маску подтверждёнными светлыми/обведёнными буквами, отделить прозрачные плашки от однотонных баллонов и не возвращать буквы при вклейке. Принимать изменения по фиксированному сравнению всех локальных пар.

## Technical Context

Python 3.10–3.13, существующие NumPy/OpenCV/Pillow, ONNX-детектор и TorchScript LaMa. Новых зависимостей нет. Windows/Linux, все поверхности используют PagePipeline.clean. Локальный output/ для опытов. Проверки: pytest синтетики и scripts/eval_retouch.py, PNG без JPEG-шума. Локальные ROI вместо дополнительных полностраничных OCR, модель загружается один раз.

## Constitution Check

До и после проектирования: v2 сохраняется; новый вспомогательный алгоритм в src/components/retouch_ink.py; diff ограничен очисткой и проверками; комментарии на русском; локальные страницы/результаты не коммитятся; качество заявляется только для проверенного корпуса. Настройки, API, runtime и поверхности не меняются. Нарушений нет.

## Project Structure

- src/components/retouch_ink.py — подтверждение светлых букв и обратной обводки.
- src/components/text_segmenter.py, adaptive_text.py — интеграция с сохранением существующих путей.
- src/components/lama_inpainter.py, src/page_pipeline.py — политика заливки и полная замена ядра.
- scripts/eval_retouch.py — фиксированные детекции, baseline, контроль с разметкой пользователя.
- tests/unit/test_retouch_ink.py, test_lama_inpainter.py и существующие интеграционные проверки.
- docs/AUTOMATIC_RETOUCH.md — ограничения и воспроизводимая приёмка.

## Implementation Strategy

Сохранить baseline всех пар, добавить синтетические проверки, внести небольшие изменения и проверить целевые страницы. Затем общий прогон, исследование каждой регрессии и визуальная проверка. При необходимости сужать применимость эвристик, не подгоняя под имя файла. Завершить converge.
