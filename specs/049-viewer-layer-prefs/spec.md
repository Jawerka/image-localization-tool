# Feature Specification: Состояние слоёв просмотрщика и очередь во вкладке

**Feature Branch**: `049-viewer-layer-prefs`
**Created**: 2026-10-20
**Status**: In Progress

**Input**: User description: "Сохранять состояние двух слоёв просмотрщика между запусками и убрать дублирующий блок очереди из вкладки «Страницы»."

## User Scenarios & Testing

### User Story 1 — Слои помнят последний выбор (Priority: P1)

Как пользователь редактора, я хочу, чтобы видимость рамок и маски сохранялась между запусками и не сбрасывалась при смене страницы или проекта, чтобы каждый раз продолжать с тем же видом канваса.

**Why priority**: Это основная ценность изменения; сейчас оба слоя всегда включены после запуска.

**Independent Test**: Выключить слои кнопками или клавишами `L`/`M`, перезапустить приложение и открыть проект: состояние обоих слоёв совпадает с последним выбором. Проверяются все четыре комбинации.

**Acceptance Scenarios**:

1. **Given** сохранённые `viewer_show_boxes=false` и `viewer_show_mask=true`, **When** приложение запускается, **Then** рамки скрыты, маска видна.
2. **Given** любая из четырёх комбинаций слоёв, **When** пользователь закрывает и снова запускает приложение, **Then** восстанавливается именно эта комбинация.
3. **Given** старые настройки без новых полей, **When** приложение запускается, **Then** оба слоя включены, как раньше.
4. **Given** пользователь переключает слой кнопкой, **Then** изменение сразу уходит в `/api/settings` и сохраняется в `settings.json` в `data/`.
5. **Given** пользователь переключает слой клавишами `L` или `M`, **Then** сохраняется то же состояние, что и у кнопки.
6. **Given** пользователь быстро переключает слой несколько раз, **When** запросы завершаются, **Then** на диске остаётся последнее выбранное состояние.
7. **Given** пользователь создаёт регион при скрытых рамках, **When** рамки включаются автоматически, **Then** включённое состояние тоже сохраняется.
8. **Given** пользователь меняет страницу или проект, **When** он возвращается, **Then** выбор слоёв не сбрасывается.
9. **Given** запись настройки не удалась, **When** пользователь переключает слой, **Then** показывается сообщение об ошибке, приложение продолжает работать.

### User Story 2 — Очередь показывается только во вкладке «Очередь» (Priority: P2)

Как пользователь, я хочу видеть блок управления очередью только во вкладке «Очередь», чтобы вкладка «Страницы» не дублировала прогресс и действия обработки.

**Why priority**: Убирает уже подтверждённое дублирование и сохраняет единое место для управления очередью.

**Independent Test**: Запустить обработку, открыть «Страницы» и «Очередь»: блок очереди есть только во второй вкладке, общий прогресс в подвале виден в обеих.

**Acceptance Scenarios**:

1. **Given** активная обработка, **When** открыта вкладка «Страницы», **Then** блока очереди нет, а список страниц и подвал с общим прогрессом видны.
2. **Given** активная обработка, **When** открыта вкладка «Очередь», **Then** видны блок очереди и список очереди.
3. **Given** обработка не запущена, **When** открыта «Очередь», **Then** блок очереди остаётся доступным, как и раньше.

### Edge Cases

- Настройки без новых ключей считаются как `true` для обоих слоёв.
- Небулево значение нового ключа считается `true`, повреждённый `settings.json` обрабатывается существующим механизмом настроек.
- При нескольких быстрых переключениях промежуточные состояния могут не попасть на диск, последнее обязано попасть.
- Ошибка записи не откатывает видимость слоя в текущей сессии.

## Requirements

### Functional Requirements

- **FR-001**: `AppSettings` MUST содержать независимые `viewer_show_boxes` и `viewer_show_mask` с дефолтом `true`.
- **FR-002**: `Config` MUST содержать те же поля с дефолтом `true` согласно правилам проекта.
- **FR-003**: Неизвестные или отсутствующие ключи в старом `settings.json` MUST давать оба слоя включёнными.
- **FR-004**: `ViewerState` MUST применять сохранённые значения до открытия страницы при bootstrap.
- **FR-005**: Переключение кнопками и клавишами `L`/`M` MUST немедленно запускать сохранение через существующий `PUT /api/settings`.
- **FR-006**: Сохранение MUST быть последовательным: при быстрых переключениях последнее состояние не теряется.
- **FR-007**: Ошибка сохранения MUST показываться пользователю и не блокировать работу.
- **FR-008**: Переключение страниц и проектов MUST NOT сбрасывать выбор слоёв.
- **FR-009**: Автоматическое включение рамок при создании региона MUST сохраняться.
- **FR-010**: `pages_rail.dart` MUST NOT показывать `_BatchBlock` во вкладке «Страницы».
- **FR-011**: Вкладка «Очередь» MUST сохранять `_BatchBlock` и `_QueueList`.
- **FR-012**: Общий прогресс в `_Footer` MUST оставаться доступным в обеих вкладках.

### Key Entities

- **Настройки просмотрщика**: два булевых ключа в `AppSettings`, общие для приложения и хранящиеся в `data/settings.json`.
- **Состояние слоёв**: текущие `showBoxes` и `showMask` в `ViewerState`, синхронизируемые с настройками.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Все четыре комбинации слоёв восстанавливаются после перезапуска.
- **SC-002**: Старые настройки без новых полей дают оба слоя включёнными.
- **SC-003**: Кнопки, `L`/`M`, смена страницы и создание региона оставляют на диске последнее состояние.
- **SC-004**: При активной обработке блок очереди отсутствует на «Страницах» и присутствует на «Очереди».
- **SC-005**: `flutter analyze`, `flutter test` и профильные Python-тесты настроек проходят.

## Assumptions

- Настройки общие для приложения, а не для страницы или проекта.
- Схема `settings.json` остаётся версии 1; новые ключи читаются как известные поля.
- Блок очереди и его действия уже реализованы и не меняются.
