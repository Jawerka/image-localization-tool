# Research: Runtime Wheelset (schema 2)

**Feature**: 032-runtime-wheelset | **Date**: 2026-10-11

## 1. Источники колёс: доступность и ретеншн

- **Решение**: URL файлов манифеста указывают напрямую на `files.pythonhosted.org` (PyPI CDN) и
  `download.pytorch.org`; колёса не дублируются ассетами GitHub.
- **Обоснование**: URL PyPI содержат хэш и иммутабельны; HEAD `files.pythonhosted.org` отдаёт 200 +
  `Content-Length` (проверено на колесе argostranslate 1.11.0); PyTorch CDN жив для старых серий
  (cu101/cu118/cu121 — 200). Дублирование cu128 (≈2.5 ГБ) ассетами GitHub бессмысленно.
- **Альтернативы**: зеркалирование колёс в релиз (гигабайты трафика/хранения, ломает cache/CDN);
  собственный патч-веб (лишняя инфраструктура).

## 2. pip как резолвер и источник url/sha256

- **Решение**: два шага генератора:
  1) `pip install --dry-run --ignore-installed --report resolve.json <спека>` — резолв и пины без установки;
  2) `pip download --only-binary=:all: --no-deps -d <stage> --report download.json <пины>` — файлы,
     `download_info.url` + `archive_info.hashes.sha256` — готовые `files[]`.
- **Обоснование**: pip 26.0.1 в венве (все флаги есть); torch-индекс зеркалит зависимости
  (sympy, filelock, typing-extensions, networkx, jinja2 → 200), поэтому резолв — в один проход; CI не
  устанавливает torch в venv (главное ускорение против сборки `.7z`).
- **Альтернативы**: свой резолвер/парсер индексов (сложно и хрупко); `pip download` с зависимостями в один
  шаг (не даёт отдельного freeze-файла и «пины из freeze»); poetry/pdm (чужие локи, лишние зависимости).

## 3. AUTOMATIC1111: паттерн пин-файлов (проверено по репозиторию)

- **Факты**: `requirements_versions.txt` с полными пинами лежит **в репозитории**; torch ставится отдельной
  командой `TORCH_COMMAND` (env, дефолт с `--extra-index-url https://download.pytorch.org/whl/...`);
  `requirements_met()` сверяет пины с установленным через `importlib.metadata`+`packaging`; колёса/торч не
  публикуются ассетами GitHub; переопределения остальных источников — env-переменные (`REQS_FILE`, `XFORMERS_PACKAGE`…).
- **Решение для нас**: пин-файлы `locks/py310-<os>.lock` версионируются в репозитории (ревью в PR);
  ассеты релиза — манифест и `packs-linux.json`; escape hatch — `ILT_RUNTIME_MANIFEST_URL` (аналог
  `TORCH_COMMAND`), документированный пример; CI проверяет воспроизводимость linux-лока перегенерацией.
- **Альтернативы**: только релизные ассеты локов (след в релизе, но не в PR-ревью); без локов вообще
  (нет воспроизводимости и дрейф-контроля).

## 4. Распаковка колёс клиентом

- **Решение**: пофайловая распаковка `zipfile`; порядок — сортировка по имени колеса; zip-slip-проверка
  каждого entry (как в 7z-ветке); пропуск `.data/` (консольные скрипты не нужны — импортируем библиотеку);
  `dist-info`/`RECORD` сохраняются (`importlib.metadata` — по ним).
- **Обоснование**: `extractall` не даёт контроля конфликтов, детерминизма и проверки путей; на Linux
  zipfile не восстанавливает exec-bit, но `.so` он не нужен (импорт — по ELF без exec-бита).
- **Альтернативы**: `wheel`-библиотека (лишняя зависимость в базе); `pip install --target` (в frozen-базе
  нет pip; тянет скрипты и `.data`, которых мы явно не хотим).

## 5. Правило конфликтов и детерминизм

- **Решение**: при совпадении пути из двух колёс: одинаковое содержимое — skip (идемпотентно), разное —
  ошибка установки с очисткой `.tmp`; порядок обработки колёс — по имени файла.
- **Обоснование**: репо-файлы разных колёс (`*.dist-info/RECORD` уже разделены каталогами; дубликаты
  бывают у namespace/скриптов) — детерминированный отказ лучше «последний победил».
- **Альтернативы**: «последний победил» (невидимые поломки), «первый победил» (зависит от порядка распаковки).

## 6. Манифест schema 2

- **Решение**: `{schema: 2, app, packs[]}`; запись `format:"wheels"`: `files[{name,url,sha256,size_bytes}]`,
  суммарный `size_bytes`; `sha256` верхнего уровня — только у archive-записей (совместимость schema 1);
  манифест адресуется по версии приложения (`releases/download/v{__version__}/…`), фоновое обновление —
  манифест той же версии, поэтому старые клиенты schema 2 не видят.
- **Обоснование**: у ключа конца и края; per-file sha — защита от подмены на CDN и от частичной установки;
  сумма даёт честный размер UI и прогресс.
- **Альтернативы**: один sha на пак (нет проверки каждого файла до распаковки), вложенный `archive`-объект
  (сложнее).

## 7. Гейт релиза

- **Решение**: Tier 1 — структурная валидация (сумма/sha/размеры) + HEAD всех URL (200; `Content-Length`
  == `size_bytes`, если заголовок есть) в пуле потоков; Tier 2 (`--deep`) — установка `torch-cpu` во
  временный каталог + `import torch` в subprocess, кэш `deep.json` по sha256(setup, portable, server, manifest).
- **Обоснование**: HEAD-проверки подтверждены для обоих CDN (200+Content-Length); глубокая проверка
  занимает минуты — кэш по входам исключает повторные прогоны без нужды.
- **Альтернативы**: скачивать все файлы (~гигабайты) в Tier 1; без кэша (каждый прогон заново).

## 8. Версии и пины

- **Решение**: torch 2.11.0 (`cpu`/`cu128`) под Python 3.10; индексы резолва: torch —
  `download.pytorch.org/whl/{cpu,cu128}` + PyPI страховкой, argos — PyPI (зависимости).
  Версия приложения 1.0.1.
- **Обоснование**: совпадает с текущими паками 1.0.0 (torch 2.11.0); версия приложения 1.0.1.
- **Альтернативы**: git-спека argostranslate (как в dev-`requirements.txt`) — не поддержана
  `pip download` with binary-only и не даёт иммутабельного URL (см. §9).

## 9. argostranslate: почему git-колесо, а не PyPI

- **Факты (проверено)**: PyPI-релиз `argostranslate==1.11.0` объявляет `stanza==1.10.1`
  жёсткой зависимостью, `translate.py` импортирует `sbd.py`, а тот — `import stanza` без
  `try/except`; stanza требует torch. Резолв с PyPI даёт 70 пакетов, 216.5 МБ (torch 2.14.1
  на 124 МБ внутри). В git-ветке 1.11.1 (`try: import stanza except ImportError`) stanza —
  optional extra; старый `.7z`-пак argos (39 МБ) собирался именно так.
- **Решение**: генератор собирает колесо `argostranslate-1.11.1-py3-none-any.whl` (41 КБ)
  из официального git по пину `17ed1a9b055c5ba1b51d76b683bbb0c64e2a4a88` через
  `pip wheel --no-deps`; колесо публикуется одним ассетом релиза (URL — GitHub), остальные
  файлы — PyPI/torch-CDNs. CI не пересобирает колесо, а скачивает ассет из draft (ожидание
  с ретраями) — sha совпадает у обеих платформ (wheel `py3-none-any`).
- **Обоснование**: это A1111-подход (`CLIP_PACKAGE` — архив официального git по коммиту),
  адаптированный к замороженному клиенту: единственная сборка вместо сборки на машине
  пользователя; torch-free состав сохраняется.
- **Альтернативы**: PyPI 1.11.0 + stanza + torch (216 МБ и дубль torch — против дизайна);
  1.10.0/1.9.6 (тоже жёсткий stanza, старые API); собственная правка PyPI-колеса (патч
  чужого кода хуже сборки из официального коммита).
