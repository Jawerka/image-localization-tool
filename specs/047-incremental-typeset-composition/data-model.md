# Data Model: Частичная композиция текста

## Предыдущий и новый документ

Существующий `PageDocument` остаётся авторитетной моделью регионов и version. Worker job для безопасной локальной правки может содержать `previous_document` и список `changed_region_ids`. Предыдущий документ нужен только для проверки, какие слои имели старые bounds и пересекающиеся bubble-зависимости.

## Provenance результата

Необязательные поля в `page.json`:

- `result_document_version`: версия документа, по которому был собран `result.png`.
- `result_clean_sha256`: SHA-256 байтов активного `clean.png` при композиции результата.
- `result_region_bounds`: словарь `region_id -> [left, top, right, bottom]`, полуоткрытые координаты финальных видимых чернил в пикселях исходной страницы; null — регион не дал видимых чернил.

Метаданные действительны только вместе с существующими `clean.png` и `result.png`, совпадающей версией и fingerprint. Если любое условие не выполнено, объект не используется и запускается обычный полный render.

## Область частичной композиции

Временный объект вычисляется из старых и новых ink-bounds изменённых регионов плюс перекрывающихся соседей при смене наличия текста. Rectangle округлён до целых пикселей и ограничен размерами clean-страницы. Для непустого rectangle хранится число пикселей; путь допустим при доле не выше 0.25.

Область не сериализуется отдельно: после успеха новые bounds и provenance сохраняются вместе с новым result. Отмена, ошибка, stale job или отсутствие артефактов не должны обновлять provenance результата.

## Жизненный цикл

1. Полная вёрстка формирует overlay и bounds.
2. После успешного version-checked commit сохраняется result и provenance.
3. Следующая typeset-правка проверяет provenance и собирает старый/new dirty rectangle.
4. Результат crop композиции сохраняется с новой document version и bounds.
5. Любое изменение clean страницы сбрасывает provenance; старые `page.json` без полей остаются валидными и используют полный путь.
