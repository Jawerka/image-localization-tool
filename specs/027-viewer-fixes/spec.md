# Feature Specification: Viewer Fixes — канвас, Space-рука, тема, превью, размеры

**Feature Branch**: `027-viewer-fixes`

**Created**: 2026-10-10

**Status**: Draft

**Input**: Пользовательский баг-репорт после cutover (026): «Вписать» и «По ширине» показывают крошечный лист, кисть рисует выше-левее курсора, Space не включает «Руку», диалоги/оверлеи светлые при тёмной теме, в левом рельсе нет превью страниц, поиск и «Добавить регион» слишком низкие. Причина первого блока — двойной transform: `ScenePainter.paint()` применяет `canvas.translate/scale`, хотя матрицу уже применяет `InteractiveViewer` (решение спайка 023 — `uncached`). Режимы «Отбор | Ретушь | Прогон» в 027 не меняются — фиксируется только текущая семантика (кода не касаемся).

## Research: масштабы Windows (вывод)

Пользователь предположил проблему с «двумя масштабами Windows». Проверено: у Windows действительно два независимых механизма — **масштаб дисплея** (DPI, 100–350 %, отсюда режимы DPI-awareness) и **масштаб текста** (Специальные возможности → Размер текста, 100–225 %, влияет только на шрифты). Flutter-хост объявлен `PerMonitorV2` (`windows/runner/runner.exe.manifest`), движок получает физические пиксели и отдаёт их приложению в **логических** пикселях (`MediaQuery.devicePixelRatio` — множитель); события указателя, размеры `CustomPaint` и матрица зума живут в одном логическом пространстве — пересчёт между DPI-пространствами в канвасе не выполняется (и не нужен). Масштаб текста геометрию не двигает и на смещение штриха влиять не может. Источники: Microsoft «High DPI Desktop Application Development on Windows» (DPI awareness: unaware → bitmap-stretch; PerMonitorV2 → `WM_DPICHANGED`, raw pixels), Flutter API `MediaQueryData.devicePixelRatio`. Баг «маленький лист + штрих выше-левее» объясняется ровно двойным применением одной и той же матрицы (scale² и двойной сдвиг) — DPI ни при чём; отдельного кода под Windows-DPI не требуется.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Зум и инструменты попадают в сцену (Priority: P1)

Пользователь нажимает «Вписать»/«По ширине» в доке или Ctrl+0 — лист вписывается в сцену целиком (как в веб-просмотрщике). Кисть/лассо рисуют строго под курсором; рамки, ручки и подписи регионов остаются на своих местах при любом масштабе.

**Why this priority**: это блокирующая регрессия после 026 — редактор практически неработоспособен.

**Independent Test**: `ScenePainter` на recorded-canvas при `scale≠1` и ненулевом сдвиге: пиксель штриха попадает в координату листа, а не в удвоенно-масштабированную. Живой прогон: «Вписать»/«По ширине» заполняют вьюпорт, мазок ложится под курсором.

**Acceptance Scenarios**:

1. **Given** открытая страница, **When** «Вписать» (кнопка дока, клик по «N %», Ctrl+0), **Then** лист виден целиком с полями 16 px, как `ViewTransform.fit`.
2. **Given** открытая страница, **When** «По ширине», **Then** ширина листа равна ширине вьюпорта минус поля, вертикальная прокрутка в пределах клампа.
3. **Given** инструмент «Кисть», **When** пользователь ведёт ЛКМ, **Then** превью-штрих и записанный штрих лежат под курсором (координаты листа через один `toScene`), без сдвига вверх-влево.

### User Story 2 - Space — временная «Рука» (Priority: P1)

При зажатом Space курсор меняется на «grab», ЛКМ панорамирует лист; выбранный инструмент не меняется, кружок кисти скрыт. Отпустили Space — всё вернулось. Guard ввода (фокус в текстовом поле, открытый оверлей) не активирует руку.

**Why this priority**: заявленный сценарий из хоткеев канваса (023), сейчас не работает.

**Independent Test**: виджет-тест: Space → `MouseRegion.cursor == grab`, `viewer.tool` прежний, кружок кисти отсутствует; keyup → курсор и кружок вернулись.

**Acceptance Scenarios**:

1. **Given** инструмент «Кисть», **When** зажат Space, **Then** курсор `grab`, кружок кисти скрыт, `tool` остаётся `brush`.
2. **Given** зажатый Space, **When** ЛКМ протяжка, **Then** лист панорамируется (`panBy`), штрих не рисуется.
3. **Given** Space отпущен, **Then** курсор и кружок кисти возвращаются к прежнему инструменту.
4. **Given** фокус в поле ввода или открыт оверлей, **When** Space, **Then** рука не активируется (символ идёт в поле / хоткей игнорируется).

---

### User Story 3 - Диалоги и оверлеи следуют теме (Priority: P1)

При тёмной теме («dark» или system-dark) диалог «Неприменённые правки», настройки, сети, экспорт, F1-хоткеи, выход, воркер и снекбары — тёмные; при светлой — светлые.

**Why this priority**: сейчас диалоги/экраны рендерятся дефолтной светлой Material-темой независимо от настройки — выглядит сломанным.

**Independent Test**: виджет-тест: bootstrap `theme=dark` → `settings-screen` и `viewer-leave-dialog` имеют `Brightness.dark` и тёмную палитру; `theme=light` → светлые.

**Acceptance Scenarios**:

1. **Given** настройка «Тёмная», **When** открывается любой оверлей/диалог, **Then** фон и текст — тёмной палитры (`IltPalette.dark`).
2. **Given** настройка «Светлая», **Then** те же поверхности светлые.
3. **Given** «Системная», **Then** тема следует системной (themeMode.system), live-preview темы в настройках работает.

---

### User Story 4 - Превью страниц в левом рельсе (Priority: P2)

В списке страниц у каждой строки — миниатюра 42×58 (серверный `thumb`) со статус-точкой, номер, имя, статус, прогресс; миниатюра обновляется после прогона; без доступного изображения — плейсхолдер; drag-reorder и клики работают как раньше.

**Why this priority**: макет (022/024, `.prow__thumb`) и запрос пользователя; без превью список менее читаем.

**Independent Test**: виджет-тест: строка содержит `pages-thumb-{id}`, высота строки ~66 px, клик по `page-row-*` по-прежнему выбирает страницу; при отсутствии API — плейсхолдер.

**Acceptance Scenarios**:

1. **Given** страница с готовым `thumb`, **When** список отрисован, **Then** в строке видна миниатюра 42×58 с точкой статуса (цвет по статусу).
2. **Given** `thumb` не готов (404/нет API), **Then** на месте миниатюры плейсхолдер, строка и клики работают.
3. **Given** завершился прогон и сервер обновил `thumb`, **Then** ключ `id|status` заставляет миниатюру перезагрузиться.
4. **Given** активная/выбранная страница, **Then** подсветка строки и кнопка меню сохранены; reorder не ломается.

### User Story 5 - Высоты контролов (Priority: P2)

Поле «Поиск по имени» в левом рельсе — ~46 px, кнопка «Добавить регион» — ~56 px; макеты `web/mockups/next` приведены к этим высотам (модификаторы `.in2--tall`, `.b2--tall`).

**Why this priority**: косметика, заявленная пользователем; тривиальна и безопасна.

**Independent Test**: виджет-тест: `pages-search` высотой 46; `inspector-add-region` высотой 56. Визуальная сверка макетов.

**Acceptance Scenarios**:

1. **Given** редактор, **Then** поиск — 46 px, текст центрирован по вертикали.
2. **Given** вкладка «Текст» инспектора с документом, **Then** «Добавить регион» — 56 px.
3. **Given** `main-editor.html`, **Then** поле поиска и кнопка используют классы-модификаторы и совпадают с Flutter по высоте.

---

### User Story 6 - Справка по режимам (Priority: P3)

Пользователь понимает текущую семантику «Отбор | Ретушь | Прогон». В 027 кода режимов не касаемся — фиксируем асинхронную справку и явно выносим полную семантику в отдельную фичу.

**Independent Test**: текст справки в `spec.md`/ответе; код `setMode` не изменён.

**Acceptance Scenarios**:

1. **Given** текущая сборка, **Then** режим (кроме «Прогон») влияет только на визуальное состояние сегмента; «Прогон» дополнительно открывает вкладку «Отчёт» инспектора, пока идёт batch.

---

### Edge Cases

- Зум до/после появления изображения: `setImageSize` пересчитывает fit, как раньше; двойного transform нет при `scale == 1` и `scale != 1`.
- Space зажат, пользователь ушёл в поле ввода и отпустил Space — состояние руки должно сброситься (keyup обрабатывается и при `_isTyping`).
- Оверлей поверх зажатого Space: после закрытия оверлея рука не остаётся «залипшей».
- Миниатюра недоступна (404, битый JPEG, сайдкар не отвечает) — строка не ломается, показывается плейсхолдер; запросы не ретраятся бесконечно.
- Быстрая смена статуса страницы (queue → running → done) не плодит дубликаты декодов: LRU ~64 на ключах `id|status`.
- Миниатюры не участвуют в документе/правках: клики, выделение, меню, reorder без изменений.
- Очень длинное имя файла — ellipsis, строка 66 px не разъезжается.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: `ScenePainter.paint()` MUST рисовать сцену в координатах листа и MUST NOT применять `translate`/`scale`; единственный владелец transform — `InteractiveViewer` (`_syncTransform`). Компенсации `1/scale` для экранных размеров (рамки, ручки, чипы, штрих черновика) сохраняются.
- **FR-002**: «Вписать»/«По ширине» (кнопки дока, клик по значению зума, Ctrl+0) MUST давать масштаб из `ViewTransform.fit`/`fitWidth` без квадратичного масштабирования.
- **FR-003**: Превью и запись штрихов/лассо MUST использовать координаты листа из `session.transform.toScene`; визуальное превью кисти (кружок) остаётся в экранных координатах.
- **FR-004**: Space (если канвас активен и клавиатурный ввод не заблокирован guard'ом) MUST давать временную «Руку»: курсор `grab`, панорама ЛКМ, выбранный инструмент не меняется, кружок кисти скрыт; keyup MUST возвращать прежнее состояние, включая случай keyup при фокусе в поле ввода.
- **FR-005**: `MaterialApp` MUST получать `theme`/`darkTheme`/`themeMode` из `buildIltTheme` (текущие `themeName`, `uiScale`; `system` → `ThemeMode.system`), чтобы `showDialog` и оверлеи вне `Theme` оболочки следовали настройке.
- **FR-006**: Левый рельс MUST показывать миниатюру страницы (42×58) из `GET /api/pages/{id}/image/thumb` с точкой статуса; загрузка и кэш — `WorkspaceState.loadThumbnail()` + LRU ~64 по ключу `{id}|{status}`, декод `targetWidth ≈ 84`; при недоступности — плейсхолдер; существующие клики/выделение/reorder сохраняются.
- **FR-007**: Поле «Поиск по имени» MUST иметь высоту ≈46 px (без обрезки `isDense`), кнопка «Добавить регион» ≈56 px.
- **FR-008**: Макеты `web/mockups/next` MUST получить модификаторы `.in2--tall` (46 px) и `.b2--tall` (56 px) и применить их в `main-editor.html` (существующие стили не переписываются).
- **FR-009**: Новые тесты: пиксельный тест `ScenePainter` (защита от двойного transform), Space-рука (курсор/инструмент/кружок), тема диалога и оверлея (dark/light), превью и высоты в рельсе; регрессий pytest/Flutter-наборов нет.
- **FR-010**: Семантика режимов «Отбор | Ретушь | Прогон» в 027 MUST NOT меняться кодом; текущая модель (mode + вкладка «Отчёт» при busy/«Прогоне») фиксируется как справка, полная семантика — отдельная фича.

### Key Entities

- **ScenePainter**: пасс сцены в координатах листа; `scale` берётся из `session.transform` только для компенсации экранных размеров.
- **CanvasSession.spaceDown**: состояние временной руки; выставляется только через хоткей-хендлер (guard ввода/оверлея), сбрасывается на keyup.
- **PageThumb**: виджет миниатюры; статический LRU-кэш `id|status → ui.Image`, плейсхолдер, ключ `pages-thumb-{id}`.
- **IltTheme (MaterialApp)**: `theme`/`darkTheme`/`themeMode` из `buildIltTheme`, покрывает Navigator-overlay (диалоги) и оверлеи `ShellRoot`.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: «Вписать»/«По ширине» на открытой странице дают лист, вписанный в сцену; расхождение центра мазка и курсора отсутствует (пиксельный тест + визуальный прогон).
- **SC-002**: Space: курсор `grab`, tool не изменён, кружок скрыт; после отпускания — прежний инструмент; guard ввода не активирует руку.
- **SC-003**: При `theme=dark` диалог «Неприменённые правки» и оверлей настроек — `Brightness.dark`/`IltPalette.dark`; при `light` — светлые.
- **SC-004**: Строка страницы ~66 px с миниатюрой 42×58 и статус-точкой; плейсхолдер без API; клик/reorder без регрессий.
- **SC-005**: `pages-search` = 46 px, `inspector-add-region` = 56 px; макеты не расходятся с Flutter.
- **SC-006**: `flutter analyze` — 0 issues, `flutter test` зелёный; pytest без новых падений.

## Assumptions

- Проблема «маленький лист / штрих выше-левее» — двойной transform, а не Windows-DPI (см. Research); код под DPI не добавляется.
- Серверный `thumb` (160 px, JPEG) уже пишется store/worker; отдельный эндпоинт не нужен, 404 обрабатывается плейсхолдером.
- Полная семантика режимов (скрытие кисти в «Отборе», автосмена инструмента и т.п.) — отдельная фича; в 027 не реализуется.
- Батч-раскладка `main-batch.html` вне объёма; макеты правятся только в `web/mockups/next`.
