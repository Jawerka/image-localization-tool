# Implementation Plan: Большие изображения

**Branch**: `codex/006-large-image-upload` | **Date**: 2026-11-03 | **Spec**: [spec.md](spec.md)

## Summary
Увеличить ограниченный потолок тела LAN API до 64 МиБ. Публиковать max_body_bytes в health. Расширение сериализует multipart один раз в Blob, проверяет точный размер до POST, затем отправляет те же байты. Старый health без лимита означает 20 МиБ. Не сжимать и не уменьшать оригинал.

## Technical Context
Python 3.10–3.13, стандартный HTTPServer; JavaScript MV3, Fetch/Response/Blob. Новых зависимостей, настроек и хранения нет. Windows/Chromium и Linux LAN; Firefox сохраняет сборку. Проверки: pytest и node:test. При превышении лимита POST не производится. Для 401/429 сохраняются существующие сообщения; 413 получает понятный текст даже без JSON. TypeError вне fetch не считается сетевой ошибкой.

## Constitution Check
До и после проектирования: I — пайплайн v2 без изменений; II — изменения remote.py и background.js, без новых движков и настроек; III — комментарии на русском; IV — данные только локальные, секреты не журналируются; V — заявления о качестве не меняются. Соседние входы и ограничение 40 млн пикселей сохраняются. Отдельная ветка создана; PR/слияние/деплой требуют отдельного разрешения согласно конституции. Нарушений нет.

## Project Structure
- src/app/remote.py — лимит, health, текст отказа.
- extension/src/background.js — проверка тела, классификация и журнал ошибок.
- tests/unit/test_app_remote.py — health, границы, реальная передача >20 МиБ.
- tests/js/test_extension_background.mjs — отказ без POST, старый сервер, ответы и сеть.
- docs/APP.md и docs/EXTENSION.md — контракт и поведение.

## Validation
Проверить точный multipart, старый health, ошибочный лимит, 413 с JSON и без него, сетевой TypeError и локальный TypeError. Передать 29 865 297 байт корректного PNG локальному HTTP-серверу с тестовым обработчиком и подтвердить сохранность байтов. Это проверка транспорта, не качества перевода. Собрать обе версии расширения.
