# Feature Specification: Большие изображения в расширении

**Feature Branch**: `codex/006-large-image-upload`
**Created**: 2026-11-03
**Status**: Implemented — ожидает приёмки на целевой поверхности
**Input**: Исправить отказ загрузки изображения 29 865 297 байт и ложное сообщение «сервер не найден».

## User Scenarios & Testing

### User Story 1 — Загрузить большой оригинал (Priority: P1)

Пользователь переводит изображение размером около 29 МБ без ручного сжатия.
**Why this priority**: Это воспроизводимый отказ из пользовательского журнала.
**Independent Test**: Отправить корректное изображение размером более 20 МиБ и менее 64 МиБ и получить задание.
**Acceptance Scenarios**:
1. **Given** работающий обновлённый сервер, **When** отправлен оригинал 29 865 297 байт допустимых размеров, **Then** загрузка принимается без потери качества.
2. **Given** обычное небольшое изображение, **When** запущен перевод, **Then** существующий поток работает.

### User Story 2 — Понять отказ (Priority: P1)

Пользователь видит причину превышения лимита вместо сообщения об исчезнувшем сервере.
**Why this priority**: Текущее сообщение мешает диагностике.
**Independent Test**: Подключить старый сервер с ограничением 20 МиБ и попробовать большой файл.
**Acceptance Scenarios**:
1. **Given** известный лимит сервера, **When** подготовленная загрузка превышает его, **Then** передача не начинается и показан лимит.
2. **Given** сервер вернул отказ по размеру, **When** ответ обработан, **Then** причина и код отказа сохранены в журнале.
3. **Given** сервер недоступен, **When** выполняется запрос, **Then** ошибка соединения отличается от превышения размера и локальной ошибки программы.

### Edge Cases

- Ровно допустимый размер тела принимается; на один байт больше отклоняется.
- Служебные поля загрузки учитываются в размере.
- Старый сервер не публикует лимит: используется прежняя граница 20 МиБ.
- Ограничение 40 000 000 пикселей сохраняется; его отказ также показывается как отказ по размеру.
- Отсутствующий или некорректный ответ с лимитом не разрешает неограниченную загрузку.

## Requirements

### Functional Requirements

- **FR-001**: Обновлённый сервер MUST принимать тело загрузки до 64 МиБ включительно без изменения изображения.
- **FR-002**: Расширение MUST узнавать допустимый размер до передачи тела и учитывать служебные поля; для старого сервера использовать 20 МиБ.
- **FR-003**: Превышение MUST давать понятное сообщение с лимитом и отдельный код ошибки, без запуска перевода.
- **FR-004**: Ответ об отказе по размеру MUST сохранять текст сервера; отсутствие текста MUST иметь понятное сообщение по умолчанию.
- **FR-005**: Ошибки размера и локальные ошибки программы MUST не называться «сервер не найден»; журнал MUST сохранять адрес маршрута, HTTP-статус либо код сетевого отказа без секретов.
- **FR-006**: Существующие авторизация, очередь, ограничение пикселей и пайплайн v2 MUST сохраняться.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Оригинал 29 865 297 байт проходит этап загрузки на обновлённом сервере при допустимом числе пикселей.
- **SC-002**: Во всех проверках превышения размера пользователь видит причину; ни одна из них не показывает «сервер не найден».
- **SC-003**: При известном превышении передано 0 байт изображения.

## Assumptions

- Безлимитная загрузка и автоматическое уменьшение изображения не требуются.
- 64 МиБ — новый ограниченный потолок тела запроса, включая служебные поля.
- Публикация PR, слияние и деплой отдельно от реализации; реальный перевод не подменяется тестом загрузки.
