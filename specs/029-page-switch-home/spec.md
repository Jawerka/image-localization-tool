# Feature Specification: Page Switch Home — старт страницы сверху при зуме

**Feature Branch**: `029-page-switch-home`

**Created**: 2026-10-11

**Status**: Draft

**Input**: Баг-репорт после cutover: «при переключении изображения, если есть масштаб, изображение раньше перетягивалось вверх, чтобы следующее изображение сразу было сверху, чтобы продолжать чтение». В веб-редакторе это делал `web/js/viewer.js` (`ad93468`): при смене страницы `home = zoom !== "fit" && zoom !== "fit-width"`, `pinScroll()` (scrollTop/scrollLeft = 0), повторно после `layout()` и в `onImageLoad()` (картинка грузится асинхронно). В Flutter `resetForPage()` не вызывается нигде, а `openPage()` не трогает `CanvasSession` — `_transform` от прошлой страницы остаётся; `setImageSize()` для числового зума не пересчитывает, и новая страница открывается на старом смещении (короче — может оказаться вне экрана).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Новая страница начинается сверху (Priority: P1)

Пользователь читает страницу в числовом масштабе (после «+»/колеса), проматывает вниз и жмёт стрелку/страницу в списке. Следующая страница открывается с верхнего края, масштаб сохраняется — чтение продолжается с начала страницы.

**Why this priority**: регрессия после переноса на Flutter: страница открывается на чужом смещении, читать нельзя без «Вписать».

**Independent Test**: юнит-тест `viewer_state`: зум 1.0, `panBy` вниз, `openPage('p2')` → `zoomMode`/`scale` прежние, `ty == 0`; для страниц одинакового размера тоже (флаг `_pinHome` живёт до реального размера нового листа).

**Acceptance Scenarios**:

1. **Given** страница A в числовом зуме, прокрученная вниз, **When** открывается страница B, **Then** B показывается с верхнего края (`ty = 0`), масштаб сохранён, зум-режим прежний.
2. **Given** страницы A и B одинакового размера, **Then** B всё равно стартует сверху.
3. **Given** лист меньше вьюпорта по ширине, **Then** по горизонтали он центрируется (как `clamped`), по вертикали — центр, если помещается.
4. **Given** zoom `fit`, **When** смена страницы, **Then** новая страница вписана целиком (центрирование, как раньше).

---

### User Story 2 - Позиция из пакета главнее (Priority: P2)

При загрузке пакета восстановленные зум + смещение не затираются «домом».

**Independent Test**: `restoreSession()` сбрасывает `_pinHome`; после `loadPackage` смещение из `editor` применяется.

**Acceptance Scenarios**:

1. **Given** пакет с `zoom` и `scroll_top`, **When** страница открыта, **Then** положение — из пакета, не верхний край.

### Edge Cases

- Перезагрузка той же страницы (`openPage` с тем же id) не сбрасывает позицию.
- Закрытие страницы (`openPage(null)`) не трогает сессию.
- Смена страницы при `fit-width` — режим пересчитывается (верх/центр по `clamped`), как сейчас.
- Запас ¼ из 028 не мешает «дому»: `ty = 0` лежит в допуске клампа.
- Черновики жестов (лассо, предпросмотры, курсор кисти) сбрасываются при смене страницы (веб-паритет).

## Requirements *(mandatory)*

- **FR-001**: `CanvasSession` MUST иметь `homeForPage()`: сброс `_pendingScroll*`, `clearPreviews()`, `clearLasso()`, `cursor = null`; при числовом зуме MUST ставить позицию от верхнего/левого края (`ViewTransform(scale)` + `clamped`), зум MUST сохраняться; при `fit`/`fit-width` — пересчёт `_recompute()` как раньше.
- **FR-002**: `setImageSize()` MUST при активном флаге `_pinHome` заново применить домашнюю позицию по реальному размеру нового листа (включая случай совпадающих размеров) и снять флаг.
- **FR-003**: `ViewerState.openPage()` MUST вызывать `session.homeForPage()` при переходе на другую непустую страницу (`previous != next && next != null`); перезагрузка той же и закрытие — без вызова.
- **FR-004**: `restoreSession()` MUST сбрасывать `_pinHome` — восстановленное из пакета смещение приоритетнее.
- **FR-005**: Новые тесты: числовой зум → верх; сохранение зума; тот же id не сбрасывает; `fit` не ломается. Регрессий Flutter/pytest нет.

## Key Entities

- **CanvasSession._pinHome**: флаг ожидания размера нового листа после смены страницы (веб: `scrollHome`).
- **CanvasSession.homeForPage()**: хук смены страницы; координаты листа и хит-тесты не меняются.

## Success Criteria *(mandatory)*

- **SC-001**: При числовом зуме смена страницы стрелками/списком/PgUp-PgDn открывает новую страницу с верхнего края с сохранённым масштабом.
- **SC-002**: `fit`-смена страницы остаётся вписанной; тесты `029` и все прежние зелёные.
- **SC-003**: `flutter analyze` — 0 issues, `flutter test` зелёный.

## Assumptions

- Паритет именно с текущим вебом: pin только для числового зума (`fit`/`fit-width` не пинятся); `fit-width` во Flutter и так пересчитывается к верху.
- `ty = 0` без 6px-отступа веб-сцены (`--space-sm`): у Flutter своя геометрия листа и поля `clamped`.
- Python/API/воркер не меняются.
