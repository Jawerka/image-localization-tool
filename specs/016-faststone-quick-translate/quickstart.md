# Quickstart validation

1. В venv: python -m pytest tests/unit/test_quick.py tests/unit/test_app_server.py tests/unit/test_app_remote.py tests/unit/test_app_settings.py.
2. В apps/desktop: flutter test --no-pub; flutter analyze --no-pub; flutter build windows --release --no-pub.
3. Запустить desktop/ImageLocalizationTool.exe --quick "C:\images\страница 1.png" "C:\images\page2.jpg".
4. ПКМ → «Сервер…»: http://192.168.88.41:8765, одноразовый код с сервера. На ПК не нужны OCR/LaMa/Argos/LLM. Через ПКМ повторить кадр после сопряжения.
5. В FastStone 8.2 Settings → Programs добавить desktop/ImageLocalizationTool.exe с аргументами --quick (filename); использовать назначенную Alt+2. Скобки круглые. Назначение E не менять.
6. Проверить несколько файлов/кириллицу/пробелы, дедупликацию, contain и стадии. Очередь отправляет один файл одновременно; локальный worker не вызывается.
7. Открыть редактор с проектом; quick не меняет его страницы. Явное открытие кадра в редакторе создаёт отдельный проект после проверки черновика.
8. Закрыть при активной сетевой задаче, отправить следующий файл; то же quick-окно и очередь сохраняются. При простое и закрытом редакторе выход штатный.
9. ПКМ: оригинал/перевод, сохранение/конфликт, отмена/повтор, навигация, багрепорт. Пакет содержит материалы и серверные параметры при поддержке diagnostics, без секретов.
10. Отключить доступ к серверу/сопряжение: кадр показывает причину, локальная обработка не начинается. Проверить серверные ошибки модели/LLM/офлайн-пары и кадр без текста.

Ручная FastStone-цепочка и реальный перевод требуют FastStone и кода сопряжения; один успешный health не считается переводом. Серверная отмена worker и diagnostics требуют обновления серверного кода отдельным безопасным деплоем.
