# Feature Specification: Быстрый перевод из FastStone

**Feature Branch**: `codex/016-faststone-quick-translate`
**Created**: 2026-11-13
**Status**: Implemented; live FastStone acceptance pending (see validation.md)
**Input**: Отдельное простое окно быстрого перевода из FastStone; изменение относительно 001-current-state. Уточнение пользователя: перевод только на сервере http://192.168.88.41:8765 по протоколу расширения браузера.

## User Scenarios & Testing

### User Story 1 — Отправить и сразу перевести (Priority: P1)

Пользователь отправляет один или несколько файлов из FastStone. Отдельное окно показывает последний присланный оригинал, автоматически обрабатывает очередь и заменяет пиксели результатом.

**Why this priority**: Основной сценарий не требует открытия проекта и дополнительных действий.
**Independent Test**: Отправить три картинки при закрытом редакторе и дождаться трёх результатов.

**Acceptance Scenarios**:
1. **Given** приложение закрыто, **When** передан файл, **Then** открывается отдельное окно с оригиналом и бейджем очереди, перевод запускается автоматически.
2. **Given** перевод первого файла идёт, **When** прислан второй, **Then** он становится видимым с собственной позицией; первый продолжает обработку.
3. **Given** файл уже ожидает, обрабатывается или готов, **When** тот же путь прислан повторно, **Then** показывается существующий элемент без повторного перевода.
4. **Given** один файл повреждён, **When** очередь доходит до него, **Then** причина видна на его кадре, следующие файлы продолжают обработку.

### User Story 2 — Управлять картинками без оболочки редактора (Priority: P1)

Окно содержит только изображение contain на тёмном фоне, бейдж и контекстное меню.

**Why this priority**: Минимальная поверхность — определяющее свойство режима.
**Independent Test**: Действия и переходы доступны через ПКМ; колесо меняет масштаб под указателем, левая кнопка перетаскивает изображение; панели редактора отсутствуют.

**Acceptance Scenarios**:
1. **Given** идёт перевод, **When** наведён указатель на бейдж, **Then** показан этап: «Ищем текст», «Распознаём», «Переводим», «Стираем оригинал» или «Вписываем перевод»; бейдж содержит кольцо и процент.
2. **Given** перевод готов, **When** результат показан, **Then** коротко появляется ✓ и гаснет; оригинал доступен из ПКМ.
3. **Given** есть результат, **When** выбрано сохранение, **Then** предложено `{stem}_{targetLang}.png`, существующий файл требует явного подтверждения, исходник защищён от перезаписи.
4. **Given** элемент ожидает или обрабатывается, **When** выбрана отмена, **Then** отменяется только его задача; повтор возможен из ПКМ.
5. **Given** несколько элементов, **When** выбрано «Предыдущее»/«Следующее», **Then** меняется только просмотр.
6. **Given** открыт кадр, **When** прокручено колесо вверх/вниз, **Then** изображение увеличивается/уменьшается под указателем, кадр не переключается; минимальный масштаб вмещает изображение в окно.
7. **Given** кадр увеличен, **When** зажата левая кнопка и перемещена мышь, **Then** изображение движется за рукой; курсор меняется с раскрытой руки на сжатую, изображение нельзя потерять за границами окна.
8. **Given** кадр увеличен, **When** выполнен двойной щелчок, **Then** изображение снова целиком помещается в окно. Новый кадр открывается целиком; замена оригинала переводом сохраняет масштаб и положение.
9. **Given** перевод готов, **When** в ПКМ выбрано «Копировать», **Then** в системный буфер помещается полное изображение с переводом для обычной вставки, независимо от масштаба и показа оригинала. До готовности результата пункт отсутствует.

### User Story 3 — Совместная работа с редактором (Priority: P1)

Быстрое окно независимо от редактора, но отправляет изображения серверному обработчику, как расширение. Локальные модели для быстрого окна не требуются. Закрытие во время перевода скрывает окно и сохраняет серверную обработку и получение результата.

**Why this priority**: Нельзя менять открытый проект или дублировать тяжёлые модели.
**Independent Test**: Открыть редактор с проектом, отправить файлы в быстрое окно, проверить неизменность проекта и единственный обработчик.

**Acceptance Scenarios**:
1. **Given** редактор открыт, **When** файл отправлен в быстрый перевод, **Then** появляется отдельное окно и проект редактора не меняется.
2. **Given** быстрое окно скрыто во время обработки, **When** приходит следующий запуск, **Then** оно поднимается с актуальной очередью и последним присланным кадром.
3. **Given** только быстрое окно и нет незавершённых задач, **When** окно закрыто, **Then** приложение завершается штатно.
4. **Given** готовый кадр, **When** выбрано «Открыть в редакторе», **Then** редактор получает копию исходника и результата как отдельный проект; существующий проект не изменяется.

### User Story 4 — Сохранить материалы ошибки (Priority: P2)

**Why this priority**: Материалы нужны для последующих правок кода без внешнего сервиса.
**Independent Test**: Через ПКМ создать отчёт с заметкой и проверить папку материалов.

**Acceptance Scenarios**:
1. **Given** любой кадр, **When** введена непустая заметка, **Then** локально сохранены оригинал или ссылка, доступный результат, заметка, этап, статус, предупреждения, языки, версия и настройки без секретов; при наличии — фрагмент лога задачи.
2. **Given** пустая заметка, **When** запрошен отчёт, **Then** сохранение отклонено с понятным объяснением.

### Edge Cases

- PNG, JPG/JPEG, BMP, TIFF поддерживаются; прочие расширения, исчезнувшие и нечитаемые файлы образуют кадр с причиной без запуска обработки.
- Пути с пробелами и кириллицей сохраняют точное значение. Несколько путей сохраняют порядок поступления.
- Нет текста: результат равен оригиналу, краткое предупреждение, не ошибка.
- Нет сервера или сопряжения: ошибка на кадре без локального фолбэка.
- Нет модели, офлайн-пары или связи с LLM на сервере: конкретная причина на кадре; остальные задачи продолжаются.
- Удаление активного элемента сначала отменяет его задачу; чужие задачи не отменяются.
- Повтор после ошибки/отмены выполняется только явным действием ПКМ.

## Requirements

### Functional Requirements

- **FR-013**: Быстрое окно использует сервер по IP; локальный пайплайн не вызывается даже при сбое сети.
- **FR-014**: Подключение и сопряжение по одноразовому коду доступны из ПКМ «Сервер…». Токен не попадает в JSON настроек, ответы сессии и багрепорты.
- **FR-001**: Отдельное быстрое окно принимает файлы FastStone, автоматически показывает последний и переводит последовательную очередь.
- **FR-002**: Повторный запуск поднимает существующее быстрое окно; второй тяжёлый обработчик не создаётся.
- **FR-003**: Очередь и результаты изолированы от открытого проекта редактора.
- **FR-004**: Интерфейс не содержит меню «Файл», тулбара, статусбара, ряда кнопок и каталога файлов.
- **FR-005**: Бейдж отражает состояние именно видимого элемента: позицию, процент/этап, краткий успех или ошибку.
- **FR-006**: ПКМ предоставляет по состоянию оригинал/перевод, сохранение, отмену, повтор, багрепорт, открытие в редакторе, удаление и навигацию.
- **FR-007**: Повтор одного пути не создаёт дубль; оригинал никогда не меняется.
- **FR-008**: Ошибка одного элемента не останавливает остальные; неподдерживаемые форматы не обрабатываются.
- **FR-009**: Результаты и локальные отчёты хранятся в data/; отчёт никуда не отправляется и не содержит ключей LLM.
- **FR-010**: Закрытие при незавершённой обработке скрывает быстрое окно; повторный запуск восстанавливает его; закрытие без работы завершает приложение, если редактор закрыт.
- **FR-011**: Сохранение предлагает имя с языком, требует подтверждения замены и запрещает замену исходника.
- **FR-012**: Существующий запуск редактора и назначенная в FastStone клавиша E продолжают работать.
- **FR-013**: Быстрый запуск не ожидает подготовки редактора, проверок локальных моделей, GPU и установки компонентов. Редактор подготавливается однократно при первом открытии в том же процессе; IPC и очередь quick продолжают работать.
- **FR-014**: При запуске `--quick` сразу используется первое окно, без скрытого окна редактора. Оригинал распространённых форматов показывается параллельно подготовке очереди; подключение не сбрасывает уже изменённые масштаб и положение. Внешний вид, отдельное окно редактора и все действия остаются прежними.
- **FR-015**: Quick и редактор независимо сохраняют положение, размер и обычное/свёрнутое/развёрнутое состояние, включая сворачивание из развёрнутого. Восстановление происходит до первого показа без вспышки обычного окна; DPI дисплея и размер текста Windows учитываются отдельно. При отключении монитора окно переносится в доступную рабочую область. Уже работающий экземпляр по новому вызову FastStone поднимается на передний план.

### Key Entities

- **Сессия**: упорядоченные элементы, текущий кадр, отдельное хранилище результатов.
- **Элемент**: нормализованный путь, задача, статус, этап, процент, предупреждения, ошибка, исходник и результат.
- **Багрепорт**: обязательная заметка, материалы кадра и обезличенная диагностика.

## Success Criteria

### Measurable Outcomes

- **SC-001**: В серии из пяти отправленных файлов каждый допустимый файл переводится ровно один раз; максимум один файл обрабатывается одновременно.
- **SC-002**: Во всех тестах редактор сохраняет исходный набор страниц при отправке в быстрое окно.
- **SC-003**: Все перечисленные действия выполняются из ПКМ; постоянно видимых кнопок, меню «Файл» и статусбара — ноль.
- **SC-004**: После ошибки среднего файла оставшиеся файлы доходят до терминального состояния.
- **SC-005**: Багрепорт содержит все доступные материалы и ноль секретных значений из настроек/лога.
- **SC-006**: Закрытие и повторное открытие во время обработки не дублируют задания и не теряют очередь.

## Assumptions

- Целевой язык берётся из сохранённых настроек ПК; исходный определяется автоматически, как в расширении. Параметры пайплайна, LLM и модели принадлежат серверу.
- Адрес по умолчанию подтверждён пользователем: http://192.168.88.41:8765. Сопряжение отдельное от браузера.
- Багрепорт включает снимок серверных параметров, если сервер поддерживает диагностику; старый сервер явно отмечается как не отдающий снимок, локальные параметры не выдаются за серверные.
- Сессия живёт в процессе; результаты на диске сохраняются, автоматическое восстановление истории после полного выхода в v1 не требуется.
- Закрытие при ожидающей очереди также сохраняет обработку: ожидающие задания считаются незавершённой работой.
- Открытие в редакторе — явное создание отдельного проекта, без добавления страниц в прежний проект.
- ImageGlass, каталоги, сравнение папок, плагины форматов и отдельный OCR вне границ v1.
