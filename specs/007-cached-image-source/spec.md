# Feature Specification: Изображение из кэша браузера

**Feature Branch**: `codex/007-cached-image-source`
**Created**: 2026-11-03
**Status**: Implemented — проверено локально, ожидает приёмки на пользовательском сайте
**Input**: Добавить возможность загрузки из браузерного кэша при E_DOWNLOAD.

## User Scenarios & Testing

### User Story 1 — Перевести доступный сохранённый оригинал (Priority: P1)
Пользователь переводит ранее загруженную картинку, даже когда её источник перестал отвечать.
**Why this priority**: На странице картинка есть, но текущее повторное скачивание обходит кэш.
**Independent Test**: Загрузить страницу и картинку, отключить источник изображения, прочитать сохранённые байты и отправить их в перевод.
**Acceptance Scenarios**:
1. **Given** читаемый оригинал сохранён в кэше страницы, **When** выбран перевод, **Then** используются исходные байты без повторной передачи от источника.
2. **Given** доступна уже декодированная картинка, но чтение исходных байтов не удалось, **When** браузер разрешает читать её пиксели, **Then** перевод получает изображение полного исходного разрешения.

### User Story 2 — Сохранить запасное скачивание (Priority: P1)
**Why this priority**: Кэш может отсутствовать или быть защищённым.
**Independent Test**: Запретить чтение картинки со страницы и проверить скачивание расширением и его журнал.
**Acceptance Scenarios**:
1. **Given** кэш страницы недоступен, **When** выполняется перевод, **Then** расширение пробует собственный доступный кэш и сетевую загрузку.
2. **Given** все пути недоступны, **When** возвращена ошибка, **Then** журнал различает отказ страницы, HTTP-ответ и сетевой сбой, без секретов.

### Edge Cases
- Чужой origin без разрешения чтения, испорченное или пустое тело, зависший источник.
- Картинка сменила src во время чтения; переведённая подмена не используется как оригинал.
- blob/data и готовые байты работают как раньше; крупный файл не должен превышать предел передачи сообщений браузера.
- Наличие картинки на экране не гарантирует доступность байтов. Обход защиты и чтение файлов профиля браузера исключены.

## Requirements
### Functional Requirements
- **FR-001**: Перед скачиванием расширением MUST выполняться попытка чтения с использованием кэша в контексте страницы.
- **FR-002**: Если исходные байты недоступны, MUST использоваться читаемые пиксели загруженного оригинала без уменьшения разрешения; подменённая картинка запрещена.
- **FR-003**: Сбой или истечение 5 секунд на запрос страницы MUST оставлять доступным запасное скачивание расширением; оно MUST не запрещать HTTP-кэш.
- **FR-004**: Пустой либо непрозрачный ответ MUST не отправляться на перевод как изображение.
- **FR-005**: Журнал MUST различать выбранный путь и причины отказов, не записывать байты картинки, ключ сопряжения или полный подписанный URL.
- **FR-006**: MUST сохраняться поддержка blob/data, HTTP-лимиты 006, результаты переводов и защита браузера. Новые разрешения не требуются.

## Success Criteria
### Measurable Outcomes
- **SC-001**: В локальном браузерном сценарии прогретого читаемого кэша при отключённом источнике извлекаются исходные байты; повторных запросов картинки к источнику — 0.
- **SC-002**: Проверки защищённого canvas и отказа кэша завершаются запасным путём без блокировки перевода.
- **SC-003**: На fallback сохраняются исходные ширина и высота; непрозрачные и пустые ответы не используются.

## Assumptions
- При политике безопасности, запрещающей читать оба варианта страницы, остаётся обычное скачивание; гарантировать доступ ко всем внешним картинкам нельзя.
- Поля message с изображением передаются только при размере до 32 МиБ, чтобы base64 оставался ниже ограничений браузера. Более крупные файлы идут обычным путём с лимитом 006.
- Изменение относится только к расширению; Windows и LAN пересобирать не требуется. Ранее пользователь разрешил деплой во все места; для этой доработки обновляется единственная затронутая установка — расширение.
