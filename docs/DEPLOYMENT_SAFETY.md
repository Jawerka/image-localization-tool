# Безопасный деплой

Всегда выполнять настоящий dry run перед реальным деплоем на той же цели и том же артефакте. Повторять его после изменения кода, пакета, цели или параметров. Ошибка или неожиданное удаление блокирует применение. Перед записью сохранять свежие код, настройки и проекты; после — проверять health, хеши и сохранность данных.

## Windows

Сначала собрать пакет. Проверка: `scripts/deploy-windows.ps1 -DryRun`. Применение: `scripts/deploy-windows.ps1` (повторит dry run автоматически).

Копируются только desktop, sidecar, web, fonts. Модели при IncludeModels дополняются без очистки. Корень установки не зеркалируется; data, runtime, .resources, .downloads, .builtin, components и неизвестные корневые файлы не входят в обновление. Ссылки в управляемых путях и их предках отклоняются. До копирования создаётся свежая `.ImageLocalizationTool.backup-<id>` с кодом и data рядом с установкой, с сохранением NTFS-прав. Наличие и SHA256 каждого файла копии проверяются до обновления; одного exit code robocopy недостаточно. При ошибке копирования скрипт останавливается и указывает backup; автоматический откат Windows не заявляется.

## LAN CT113

Dry run: `scripts/deploy-lan.ps1 -DryRun -Report output/lan-plan.json`.

Применение: `scripts/deploy-lan.ps1 -Report output/lan-applied.json`.

Dry run реально подключается к серверу и проверяет рабочий каталог службы, место для stage/backup и хеши src/web. Загрузка и перезапуск не выполняются. Обычный запуск также начинает с плана, а перед применением повторно проверяет исходные хеши. SSH принимает только уже известные ключи; первый контакт с новым сервером настраивается отдельно.

Архив содержит только файлы манифеста. Ссылки, traversal, неизвестные члены, неправильные размеры и хеши отклоняются до остановки службы. При применении берётся блокировка, проверяется stage, останавливается служба, сохраняются data/config и изменяемый код. Затем атомарно заменяются только изменившиеся файлы. Устаревшие файлы не удаляются. При ошибке применения или health восстанавливается прежний код и перезапускается служба. Данные не заменяются при откате кода; их backup остаётся для отдельного восстановления при необходимости.

## Проверено 2026-11-04

На CT113 dry run обнаружил ровно три изменённых модуля ретуши. После повторного плана они развёрнуты, служба активна и health ready=true. Все файлы манифеста сверены. Настройки config.json/data/settings.json и 1460 файлов проектов совпали с актуальным backup.

Backup: `/opt/.image-localization-tool-deploy-backups/20261104-030457-bc0cd185`. Локальные доказательства: `output/safe-deployment/lan-dry-run.json`, `lan-applied.json`, `server-data-verification.json`, `windows-dry-run.log`.

Постоянное правило продублировано в локальном AGENTS.md и `.cursor/rules/deployment-dry-run.mdc`. Оно распространяется также на другие цели: если соответствующий инструмент ещё не поддерживает dry run, сначала добавить безопасный предпросмотр, а не пропускать правило.

Целевые проверки: 32 теста dry run, сохранения файлов/резервных копий, ложного успеха robocopy, traversal/TAR/хешей, изменения сервера после плана, нехватки места и отката после health failure. Проверки реального NTFS-копирования выполнялись с обычным доступом вне ограниченной среды. Ruff для новых помощников и тестов, git diff --check прошли.
