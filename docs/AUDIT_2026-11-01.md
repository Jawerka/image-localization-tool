## Подтверждённые дефекты

### 1. P1 — при сбое сохранения исчезает предыдущий пакет

Место: `src/app/portable_project.py:224–229`, `pack_project`.

После сборки временного ZIP функция сначала вызывает `dest.unlink()`, затем `temporary.replace(dest)`. Если замена не удалась, обработчик удаляет временный файл. Предыдущий сохранённый пакет уже уничтожен. Рабочий проект в data при этом может сохраниться, но резервная/переносимая копия теряется.

Воспроизведено во временном каталоге: создать пакет, повторить сохранение с подменой `Path.replace`, которая выбрасывает `PermissionError` только при замене итогового ZIP. После ошибки `dest.exists()` возвращает `False`.

Исправление: заменить файл атомарно без предварительного удаления; при временной блокировке Windows использовать ограниченные повторы, сохраняя старую копию при отказе. Проверка: ошибка замены должна оставлять прежний ZIP побайтово неизменным.

### 2. P2 — импорт пакета может перезаписать исходник другой страницы

Место: `src/app/portable_project.py:304–310`, `unpack_project`.

Путь из manifest сводится к `Path(image).name`. Поэтому `pages/a/page.png` и `pages/b/page.png` записываются в один `import_dir/page.png`. Обе записи проекта начинают ссылаться на последний файл, хотя документы и миниатюры могут различаться.

Воспроизведено на пакете schema 2 с красной и синей страницами: после импорта обе исходные картинки синие. Такой manifest проходит текущую валидацию. Штатный упаковщик создаёт уникальные префиксы, поэтому обычный пакет, созданный им без изменения, этот случай не вызывает.

Исправление: выдавать каждому импортируемому исходнику уникальное имя либо сохранять проверенную относительную структуру. Дубликаты идентичности страниц и путей проверять до записи.

### 3. P2 — LAN-кэш возвращает результат для другого языка или настроек

Места: `src/app/remote_cache.py:64–67`, `src/app/remote.py:160–183,721–737`.

`CacheKey` хранит исходный язык, но `token()` не включает его в хеш. Отпечаток настроек также пропускает `adaptive_text`, `discover_missing_text` и `layout_long_side`, хотя эти значения передаются в конфигурацию пайплайна. При попадании в кэш перевод вообще не выполняется.

Воспроизведено: ключи одной картинки для en→ru и ja→ru равны; переключение каждого из трёх названных параметров оставляет отпечаток прежним. Это мешает исправить неверно выбранный исходный язык и применить новые параметры обычным повторным запросом. `fresh=true` обходит проблему для конкретного запроса.

Исправление: включить исходный язык и полный набор влияющих на результат параметров в версионированный ключ. Добавить тесты изменения ключа, а не только проверки конкретной формулы. Сейчас `tests/unit/test_remote_cache.py:33` прямо закрепляет равенство ключей разных исходных языков.

### 4. P2 — перенос проекта ломает «Сбросить правки»

Места: `src/app/portable_project.py:28–33,157–170,332–350`; потребитель — `src/app/server.py:1032–1036`.

В пакет попадают текущий документ и mask/clean/result/thumb, но не автоматический снимок `auto.json`. После открытия пакета серверная команда сброса безусловно читает этот снимок и получает `FileNotFoundError`. Кнопка доступна и в web, и во Flutter.

Воспроизведено штатным циклом: создать страницу, записать `write_auto`, вызвать `pack_project`, затем `unpack_project`. `read_auto` в новом проекте завершается `FileNotFoundError`.

Исправление: переносить исходный автоматический снимок отдельным полем/файлом с обратной совместимостью. Для старых пакетов явно обозначить отсутствие снимка и отключить сброс; не выдавать текущий отредактированный документ за оригинальный автоматический результат.

### 5. P2 — Flutter предлагает форматы, которые сервер молча пропускает

Места: `apps/desktop/lib/src/ui/file_dialogs.dart:8–11`; `src/app/store.py:27,358–363`; `src/app/ingest.py:27–31`.

Диалог «Страницы и архивы» разрешает GIF и WebP. Хранилище принимает только PNG/JPEG/BMP/TIFF и пропускает остальные расширения. Пользователь выбирает разрешённый диалогом файл, но страницы не добавляются. Обратное расхождение: поддерживаемые сервером RAR/7Z/TAR не входят в фильтр Flutter.

Подтверждено сопоставлением фильтра и ветки импорта; живой системный диалог не запускался.

Исправление: согласовать фильтр с реально поддерживаемыми форматами; показывать понятную ошибку для неподдерживаемого файла. Если нужны WebP/GIF — отдельно определить преобразование и поведение анимации.

## Документация и технический долг

- `specs/001-current-state/spec.md:63` называет формат окна `.iltproj`, но Flutter сохраняет `.ilt.zip` (`apps/desktop/lib/src/ui/shell.dart:166`) и открывает ZIP. Базовую спецификацию стоит исправить вместе с проверкой пользовательской документации.
- Локальная инструкция описывает LAN-деплой как rsync, а `scripts/deploy-lan.ps1` фактически использует tar/scp и распаковку на месте. Это не то же самое, что отдельный сценарий releases/current. При следующем обновлении нужно явно выбрать и проверять нужную схему.
- Уже записанный в 001 долг по крупным `server.py`, `worker.py`, `typesetter.py` и дублированию настроек остаётся актуальным. Разделение модулей стоит делать после регрессионных тестов на сохранение, импорт и кэш; само по себе уменьшение файлов не исправляет найденные дефекты.
