# План фиксации и выпуска 1.0.3

Дата: 2026-11-09. Пользователь принял визуальный результат и запросил коммит, push и релиз.

1. Зафиксировать изменения аудита и принятую автоматическую вёрстку вместе с тестами, спецификацией и ограничениями. Согласовать версию приложения, Flutter и Compose. Локальные данные и изображения остаются вне Git.
2. Отправить ветку `codex/013-fix-audit-regressions` на GitHub, создать PR для проверки CI. Не переписывать опубликованные теги и архивы.
3. Из одного точного commit собрать Windows portable light/full CPU, Windows server, Linux server, Docker full CPU и архивы расширений. Каталоги зависимостей остаются зафиксированными.
4. Проверить Python/JS/browser/Flutter, запуск готовых сборок, автономный перевод, экспорт и проекты, обновление с сохранением данных, доступность зависимостей и лицензии. Зафиксировать доказательства и SHA256 в паспорте именно нового кандидата; результаты 1.0.2 не переносить как новые проверки.
5. Создать неизменяемый кандидат и draft `v1.0.3`, сверить байты загруженных файлов. После приёмки собранного комплекта опубликовать этот же draft без пересборки.

Публикация релиза не означает обновление действующих установок Windows/LAN/расширения. Для каждой реальной установки требуется отдельный dry run, backup кода и пользовательских данных, затем проверка установленного кода и сохранности данных по правилам проекта.

При провале сборки или обязательной проверки остановить публикацию, сохранить диагностические результаты и оставить кандидат черновиком. Непройденные проверки не помечать успешными.
