## Подтверждённые проблемы и недостающие гарантии

### B1. P1 — подготовка preview может остановиться до первого запроса — исправлено

Место: `apps/desktop/lib/src/state/viewer_state.dart:1836–1860` (на момент аудита).

`_schedulePreview()` сначала отменяет `_previewTimer`, затем при совпадающем layoutKey и статусе `loading-local` возвращается. Если пользователь меняет геометрию до запуска 250-мс таймера, прежний таймер уже отменён, новый не создаётся. Статус может остаться «Подготавливаем текст» без запросов.

Воспроизведение: существующий тест local_preview, сразу после `selectRegion('1')` вызвать `setRegionWarpBend('1', 0.25)`, затем дождаться подготовки. Получено `modes == []`, ожидались base-page/base-layer. Второй тест той же временной копии прошёл.

Исправление: таймер отменяется только после проверки переиспользования; повторный вызов при `loading-local`/`ready-local` сохраняет уже запланированную подготовку. Регрессия воспроизводится тестом `geometry change before the debounce still prepares the layer` в `local_preview_test.dart`.

### B2. P1 — раскладка не закреплена между редактированием и Done — исправлено

Выполнено: Typesetter пишет `layout_snapshot` (version, layout_key, font, font_size, lines), base-layer/exact preview отдают его в `X-Layout-Snapshot`, клиент сохраняет в регионе, финальный рендер использует строки без нового автоподбора. Ключ учитывает только входные параметры раскладки, поэтому rotation/warp не инвалидируют snapshot. Тесты: `test_frozen_layout_survives_rotation_change`, `Done saves the frozen layout snapshot from preview`.

Места: `viewer_state.dart:1918`, `src/components/typesetter.py:173`, `:1279`, `:1380` (на момент аудита).

Клиент исключает rotation из layoutKey. Python при каждом новом render по-прежнему вычисляет `_layout_spans` по текущему углу. `apply_geometry=False` отключает геометрию в конкретном вызове, но не создаёт сохраняемый объект раскладки для следующего рендера.

Контрольный пример: белая страница 400×300, bbox `(80,80,160,75)`, dialogue, строка `This is a longer sentence for a rotation layout comparison`, Typesetter 10–28, язык en:

- 0°: кегль **15**, **3 строки**;
- 35°: кегль **13**, **4 строки**;
- 65°: кегль **13**, **6 строк**.

Следовательно, сценарий «подготовить при 0°, локально повернуть на 35°, нажать Done» не закрепляет показанный результат. Тест `test_base_layer_freezes_layout_without_geometry` сравнивает два расчёта **при одинаковом угле**, поэтому этот дефект не обнаруживает.

Исправление: сохраняемый LayoutSnapshot, который потребляют preview и финальный рендер; явная инвалидация только при изменении текста/шрифта/области. Приёмка — угол меняется после подготовки, а строки/кегль/позиции в snapshot остаются теми же до и после Done и перезапуска.

### B3. P1 — кэш переиспользует слой с неподходящими размерами — исправлено

Выполнено: для `apply_geometry=False` и для финального рендера региона со snapshot используется один стабильный padding, не зависящий от rotation, warp и bend. Поэтому смена bend/preset больше не меняет source extent, а локальный painter и финальный Typesetter работают с одинаковой текстурой. Тест: `test_base_layer_extent_is_independent_of_warp_and_rotation`.

Места: `viewer_state.dart:1918`, `web/js/inspector.js:1101`, `src/components/typesetter.py:484` (на момент аудита).

Из ключа удалён весь warp. Но `_layer_pad()` зависит от вида warp, bend и rotation, а для none возможен другой путь растеризации. Локальные формулы используют ширину/высоту сохранённой текстуры; финальный рендер создаёт слой с новыми полями.

Эксперимент: страница 600×500, bbox `(150,150,160,75)`, narration, кегль 18, `This is a longer sentence`. При одинаковых строках получены:

- none: слой **120×38**, origin `(170,169)`;
- mesh: **184×114**, origin `(137,130)`;
- arc, bend 0: **130×60**, origin `(164,157)`;
- arc, bend 0.4: **332×262**, origin `(63,56)`;
- wave, bend 1: **158×88**, origin `(150,143)`.

Это не только вопрос скорости или небольшой погрешности сглаживания. После смены пресета на готовом слое меняется сама исходная область преобразования относительно финального рендера.

Исправление: общий стабильный source extent и геометрический контракт, независимые от текущего warp, либо явная версия подготовки при изменении этих зависимостей. Простое возвращение warp в ключ устранит неверное переиспользование, но вернёт серверную задержку; это временный fallback, а не достижение цели.

### B4. P1 — выбранный регион всегда оказывается поверх соседних — исправлено

Выполнено: локальный режим получает `base-page` (регионы ниже), свой RGBA-слой и `base-overlay` (регионы выше). Desktop и web рисуют overlay после выбранного слоя, поэтому порядок документа сохраняется при выборе, drag и Done. Тест: `test_preview_order_splits_below_and_above_selected`.

Места: `src/app/server.py:2387`, `apps/desktop/lib/src/ui/viewer/canvas_painter.dart:48`, `:175`; web `viewer.js`.

Base-page собирает **все** остальные надписи. Затем выбранная рисуется поверх этой картинки. Если по порядку документа выбранная надпись должна находиться ниже пересекающейся соседней, live-результат меняет порядок. Final снова использует порядок документа.

Исправление: композиция ниже/выбранный слой/композиция выше либо упорядоченный набор слоёв. Это обязательная корректность, а не необязательная оптимизация группового кэша. Приёмка — выбрать нижний из двух перекрывающихся регионов: порядок не меняется ни при выборе, ни при drag, ни при Done.

### B5. P1 — после ошибки применения нет надёжного повторного Done — исправлено

Выполнено: тело неудачного PUT возвращается в очередь, deferred-флаг и глубина истории восстанавливаются; после успешного PUT и ошибки bake повтор опрашивает результат без второго PUT. Web получил `applyDeferredEdits`: тот же retry через `failedBodies`, `saveFailedPage`, `awaitingBakePage`. Остались timeout, два 409 и поздний успех как отдельные тесты.

Места: `viewer_state.dart:749–817`, `:927–975`, `viewer_pane.dart:64`.

`commitDeferredEdits` снимает deferred-флаг до подтверждения. `_flush` удаляет pendingBody, при ошибке также очищает очередь. После успешного PUT с последующей ошибкой bake/таймаутом нет отдельного состояния «сохранено, но не запечено». После снятия isApplying условие показа пилюли может стать ложным; повторный вызов applyDeferredEdits возвращает true при отсутствии deferred/pending и ничего не повторяет.

Локальные поля иногда остаются в памяти — это не равно полноценному сохранённому черновику с retry. На повторном конфликте 409 код дополнительно очищает историю и перечитывает документ. Поэтому общее утверждение «при любой ошибке черновик и история не теряются» не подтверждается.

Исправление: отдельные состояния dirty, saving, saved-awaiting-bake, failed-save, failed-bake, applied. Не терять исходный commit snapshot, дать повтор сохранения или только bake; использовать commitId либо эквивалентную доказанную идемпотентность. Проверить timeout после фактического сохранения, 500, два 409 и поздний успех.

### B6. P1 — preview снимается раньше готовности изображения на клиенте — исправлено

Выполнено: `_reloadDetail(keepPreview: true)` сохраняет старый слой, Done ждёт декодирования result через `_awaitCurrentImage`, затем одним шагом снимает preview. Ошибка PNG оставляет черновик и preview. Тест: `applyDeferredEdits: результат не декодировался — preview остаётся`.

Места: `viewer_state.dart:805`, `:458–464`, `:477–505`.

После подтверждения render_version вызывается `_reloadDetail`. Он вызывает `_applyDetail`, который очищает preview и запускает `ensureImages()`. Загрузка и декодирование result происходят отдельно; applyDeferredEdits их не ждёт. Кроме того, `_reloadDetail` перехватывает ApiException и не возвращает признак неуспеха вызывающему коду.

Итог: атомарная замена preview готовой картинкой не реализована; возможен промежуток со старым изображением/placeholder, а успешный return не доказывает, что пользователь увидел новый результат.

Исправление: ожидать нужную revision изображения и успешное декодирование, затем единой операцией заменить слои и снять черновик. Приёмка — искусственно задержать PNG после готового render_version и отдельно вернуть ошибку PNG; preview остаётся до подтверждённой замены.

### B7. P2 — drafts не означает полный текущий документ — исправлено

Выполнено: `drafts_complete` явно объявляет полный снимок, включая новые и удалённые регионы; без него drafts по-прежнему заменяют совпавшие ID и добавляют новые. Выбранный новый регион ищется и в drafts. Ключ локальной композиции включает чужие регионы и их порядок. Тест: `test_preview_order_splits_below_and_above_selected`.

Места: `src/app/server.py:2394–2401`, `_regionLayoutKey`, `web/js/inspector.js:1135`.

Backend проходит по сохранённым `document.regions` и заменяет совпавшие ID из drafts. Новый регион из drafts не включается; удалённый из drafts сохраняется через fallback к сохранённому региону. Выбранный новый регион также сначала ищется в сохранённом документе в `_preview_region`.

Клиентский ключ слоя зависит только от выбранного региона, хотя base-page зависит от остальных. Поэтому внешнее/программное изменение соседнего региона при неизменном выбранном не гарантирует обновление фона. При обычном переключении регионов пара часто пересоздаётся, но это не общий контракт инвалидации.

Исправление: определить drafts как полный snapshot документа либо явные операции add/update/delete, сохранить порядок, отделить ключ текстуры от ключа композиции и ревизии страницы. Тест OLD→NEW доказывает лишь обновление существующего ID.

### B8. P2 — слой обрезается до преобразования, часть геометрии не покрыта — исправлено (skew через fallback)

Выполнено: base-layer для всех регионов (включая `kind=none`) захватывает целый исходный слой до вставки в страницу, поэтому origin может быть отрицательным и пиксели за краем листа не теряются. Финальный рендер региона со snapshot использует тот же слой/стабильный padding. Skew-регионы явно исключены из локального режима и идут через exact preview. Тест: `test_base_layer_keeps_padding_outside_page_edges`.

Остаётся: UI-подсказка о fallback для skew и визуальная проверка у краёв страницы.

Место: `src/components/typesetter.py:1089–1131` и локальные painters.

Было до среза: trim=False возвращал crop из overlay размером страницы с ограничением координат краями страницы. Теперь слой захватывается до вставки; см. «Выполнено» выше.

`apply_geometry=False` также отключает skew_x. В локальном painter нет эквивалентного применения skew, хотя такое поле существует в TextStyle. Для старого проекта с ненулевым skew это отдельная несовместимость, не покрытая списком новых UI-полей.

Исправление: возвращать целый исходный слой с явно заданным пространством координат и обрезать по странице после преобразований; поддержать skew либо исключить такие регионы из локального режима с объяснением.

### B9. P2 — fallback в отчётах описан сильнее, чем реализован — исправлено

Выполнено: при старте локальной подготовки и при `local-error` последняя корректная пара/preview остаётся на экране, статус явно говорит о подготовке или ошибке. Web больше не очищает exact-preview и mesh до успешного ответа. Ограничение: это устаревший fallback, а не доказательство актуальности черновика.

Места: `_schedulePreview`, `_localPreviewError`, web `runPreview`.

Flutter при начале локальной подготовки удаляет прежний exact-preview; при ошибке локальной пары очищает её и выставляет local-error, но автоматически новый exact не запрашивает. Web также убирает exact перед подготовкой. Сохранённая картинка страницы может остаться, но она не доказывает актуальность черновика.

Исправление: сохранять последний корректный preview с явной отметкой устаревания, либо запрашивать exact fallback для текущего draft. Не называть старую картинку точным текущим результатом.

## Что из перечисленного «осталось» действительно осталось

- **Web-паритет:** порядок слоёв, snapshot, `drafts_complete`, awaitable Done и локальные arc/wave/flag/ring/mesh уже есть; perspective и mesh+rotation остаются серверными, skew — fallback.
- **Совместные трансформации:** arc/wave/flag/ring + rotation поддерживаются локально через заранее повёрнутый слой (desktop и web). mesh/perspective + rotation и skew идут через exact fallback.
- **Snapshot в portable project:** сохраняется в регионе документа и проверен pack/unpack-тестом; остаётся сценарий недоступного шрифта/смены renderer.
- **Групповые слои:** порядок ниже/выше уже обеспечен через `base-overlay`; групповой кэш для нескольких черновиков и снижения стоимости подготовки не сделан.
- **Замеры p95 и памяти:** отсутствуют. Один base-page — полный RGB PNG страницы; backend подготовка слоя также использует полноразмерный overlay. Быстрый drag не означает дешёвый вход в редактирование.
- **Визуальная приёмка:** отсутствует. Сравнивать не только картинку неподвижного mesh, но и последовательности «подготовить → сменить preset/угол → drag → Done».

Процент готовности не приводится: количество реализованных кнопок и видов warp не отражает объём оставшейся работы над сохранением и совпадением результата.
