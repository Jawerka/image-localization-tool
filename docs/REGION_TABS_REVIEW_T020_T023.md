## 1. P1 — Done пересчитывает показанную раскладку

`src/app/server.py:2188`, `:2457`; `apps/desktop/lib/src/state/viewer_state.dart:2133`.

Общий `_preview_region_inputs` накладывает из draft только text/translation/bbox/style/text_position, игнорируя layout_snapshot. Desktop `_refreshDoneSnapshot` также не отправляет текущий snapshot. Поэтому запрос перед Done берёт snapshot из сохранённого документа, а не тот, который только что показал preview. Если сохранённого snapshot ещё нет, сервер рассчитывает строки с текущим углом и клиент перезаписывает ранее закреплённую раскладку.

Подтверждено через реальный HTTP API: страница 400×300, bbox (80,80,160,75), dialogue, текст `This is a longer sentence for a rotation layout comparison`. Получить base-layer при 0°, извлечь X-Layout-Snapshot, передать его в draft вместе с rotation=35 в layout-snapshot. Получено 4 строки вместо 3; первая позиция (88,83) вместо (110,89).

Это повторная вёрстка перед PUT, даже несмотря на исправленное потребление snapshot финальным пайплайном. Нужно валидировать и сохранять актуальный показанный snapshot, пересчитывая лишь при изменении входов раскладки; передавать его на desktop и учитывать на сервере. Проверять полный цикл preview(0°) → local rotation(35°) → Done, а не только наличие поля snapshot в PUT.

## 2. P1 — новый регион нельзя применить на desktop

`apps/desktop/lib/src/state/viewer_state.dart:1320`, `:2133`; `src/app/server.py:2162–2178`.

Создание региона на desktop отложено до Done. Но обязательный запрос layout-snapshot выполняется до PUT и отправляет только region_id/draft. Сервер находит ещё не сохранённый регион только через список drafts, которого в запросе нет. Возвращается 400 «Регион не найден», применение останавливается до сохранения. Повтор вызывает тот же отказ.

Подтверждено HTTP-тестом: пустая сохранённая страница, новый регион id=99 в draft, POST layout-snapshot с тем же форматом, что у клиента — 400 вместо 200.

Нужно передавать полный черновик/список регионов либо безопасно поддерживать создание целевого региона из draft на endpoint. Покрыть создание протяжкой, ввод перевода и Done, включая несколько новых регионов.

## 3. P1 — смена режима upscale/native нарушает частичную композицию

`src/page_pipeline.py:418–433`.

При появлении первого snapshot вся страница переходит из upscale в native. При этом incremental продолжает переиспользовать предыдущий result, полученный другим способом, и перерисовывает только changed_region_ids. Незатронутые регионы остаются в старой растеризации, хотя полный рендер текущего документа уже строил бы их в native.

Подтверждено экспериментом: белая страница 600×400, два независимых narration-региона; старый результат построен стандартным pipeline без snapshots. Первому региону присвоен snapshot, rotation=20. Частичная композиция с changed_region_ids=[1] вернула mode=partial. Сравнение с независимой полной композицией того же нового документа дало **8306 различных пикселей**, все в области неизменённого соседа x>=280.

При смене режима рендера нужен полный проход либо совместимый контракт для всех слоёв. Режим/масштаб должен входить в проверку пригодности предыдущего result. Имеющийся T019 проверяет один snapshot-регион и сохранение уже созданной картинки в PNG; этот переход он не покрывает.

## 4. P1 — rebake теряет необходимость очистки

`src/app/server.py:1024`; `src/app/worker.py:1394–1402`.

Rebake всегда ставит plan=typeset. Но Done запускает также clean, например после изменения bbox, маски или skip. Если clean-задача завершилась ошибкой и на диске остались прежние clean/result с прежним provenance, retry больше не требует очистки: worker проверяет отсутствие clean/provenance, но не соответствие старого clean новым изменениям документа. Получается сборка перевода поверх старого очищенного фона.

Целевой тест с зарегистрированной терминальной ошибкой apply_document(plan=clean) подтвердил, что новый job имеет plan=typeset. Требуется сохранить/восстановить исходный план либо определить необходимость clean по зависимости от документа. Проверить ошибку очистки до записи нового clean, затем retry; результат должен совпасть с успешным исходным clean+typeset, без второго PUT.
