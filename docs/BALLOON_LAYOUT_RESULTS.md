# Маски и читаемая вёрстка облачков

Дата: 2026-10-18. Изменение: `specs/034-readable-balloon-layout`.

## Реализация

В основной `bubble_contour` перенесён одобренный вариант seed85_multi56: светлая стартовая точка внутри текста, RGB-допуск 56, связность 4, объединение достаточно крупных компонент фона, прежние Canny и отступ внутрь. На трёх локальных исходниках объединённая маска диалогов **попиксельно совпала** с сохранённым экспериментом. Числа прежнего исследования (IoU 97.76%, 93.55%, 95.44%) относятся только к этому набору.

Для обычных облачков вёрстка теперь использует тот же способ выделения силуэта. Новый модуль `bubble_layout.py` перебирает кегли по убыванию, число строк и три вертикальных положения блока; динамическое программирование распределяет слова по доступной ширине каждой строки. Поэтому не предполагается монотонность успешного размещения по размеру шрифта. Это поиск максимального кегля среди рассматриваемых размещений, не доказательство глобального оптимума по всем возможным координатам.

Учитываются реальные выносы глифов, обводка и небольшой типографский запас (15% кегля, минимум 2 px). Очень длинные слова могут переноситься по имеющемуся языковому словарю. Непрерывные полосы исключают пространство между хвостами облачка. Ручной кегль имеет приоритет; SFX, документы и сложные ручные преобразования сохраняют прежний алгоритм переноса. Формат JSON не изменён.

## Сравнение методов

Три метода получили одни и те же очищенные изображения и переводы:

1. `legacy`: прежняя геометрия и прежний перенос.
2. `geometry`: новая геометрия со старым переносом.
3. `shape`: новая геометрия и перенос по непрерывным полосам формы.

| Реплика | Legacy, px | Geometry, px | Shape, px |
|---|---:|---:|---:|
| 0001, id 5, «Не помню, когда…» | 21 | 21 | **36** |
| 0001, id 7, нижнее левое верхнее облачко | 43 | 44 | **51** |
| 0001, id 9, нижнее левое нижнее облачко | 38 | 37 | **48** |
| 0002, id 3, верхнее левое облачко | 15 | 34 | **34** |
| 0008, id 2, верхнее облачко | 30 | 30 | **37** |

Некоторые ранее крупные реплики уменьшились, поскольку прежний способ допускал размещение у края или рассчитывал ширину через разрыв маски. Например, 0001/id8: 48 → 42 px. Это сознательная цена размещения целого текста внутри рассчитанной области.

Диагностика всех 27 диалоговых регионов: размещение успешно, **0 пикселей букв и обводки вне рассчитанной области до клиппинга**. Это проверка геометрии алгоритма, а не независимая проверка правильности самого силуэта по ручному эталону. Все исходные слова сохранены; translation не меняется при переносе.

Один последовательный прогон вёрстки: legacy 5.13/5.19/4.01 с, geometry 3.53/3.57/2.86 с, shape 4.26/4.04/3.18 с. Сокращены повторные измерения сложности фона для каждого кегля. Значения не являются строгим сравнением производительности: один прогон, без контроля системной нагрузки.

## Ограничения

Остаются дефекты самой очистки, в частности исходные буквы справа в нижнем левом облачке 0002 и неоднородности фона. В этой задаче перенесена одобренная маска; она не стала идеальной от улучшения вёрстки. Разметка после очистки чувствительна к мелким изменениям изображения: например, кегль 0002/id13 равен 30 px на сохранённом JPEG и 35 px на изображении в памяти обычного пайплайна. Зависимость от артефактов ретуши остаётся направлением дальнейшей работы.

Проверено на трёх известных страницах одного комикса. Независимый набор для проверки обобщения не использовался. Сборка установленного exe и деплой не выполнялись.

## Воспроизведение и локальные артефакты

`scripts/eval_balloon_layout.py --baseline-typesetter <снимок старого typesetter.py>` принимает доверенный локальный снимок старой реализации. По умолчанию читает `output/balloon-mask-study/render-candidate`, сохраняет сравнения, параметры строк и метрики в `output/layout-study`.

- `output/layout-study/metrics.json` — сравнение методов и проверка выхода глифов.
- `output/layout-study/*-comparison.jpg` — три метода рядом.
- `output/layout-study/integrated/*.png` — итоговые страницы обычного пайплайна.
- `output/layout-study/integrated/metrics.json` — результат интеграционного прогона.

Картинки, сохранённые переводы и снимок старого кода остаются локальными в игнорируемом `output/`.
